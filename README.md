# s21_mpfr

> **Status:** 🟢 **v1.27.2 (2026-10-18).** Финальный релиз.
> Библиотека чисел с плавающей точкой произвольной точности на C11.
> Проект вдохновлён [MPFR](https://www.mpfr.org/), но реализован
> с нуля в учебных целях.

Собственная реализация библиотеки чисел с плавающей точкой
произвольной точности. Продолжение проекта
[s21_math](https://github.com/pavel-maru/s21_math), где мы
упирались в ограничения `long double` (80/128/64 бит).
Здесь эти границы убираются полностью — точность задаёт
пользователь.

## Что уже готово

- Тип `s21_mpf_t` — число произвольной точности (мантисса от 2 бит).
- `init`, `init2`, `clear` — управление жизненным циклом.
- `set_prec`, `set_prec_round` — in-place смена точности
  с сохранением значения; `set_prec` использует RNDN при сужении,
  `set_prec_round` принимает явный режим округления.
- `set_ui`, `set_si`, `set_d`, `set_str` — присваивание из базовых
  типов и из строк.  `set_str` работает в любом основании
  от 2 до 36, алфавит `0-9a-z` (регистронезависимо на входе);
  в base 16 дополнительно принимает **C99 hexfloat** (`0x1.8p4`).
- `set_zero`, `set_inf`, `set_nan` — специальные значения.
- `set`, `set_round` — присваивание с режимами округления
  RNDN / RNDZ / RNDU / RNDD.
- `cmp`, `cmp_abs`, `equal`, `zero_p`, `integer_p` — сравнения,
  включая корректную работу на числах разных точностей.
- `add`, `sub`, `mul`, `div`, `neg`, `abs` — базовая арифметика,
  корректная при любой точности (включая некратные 64).
  Умножение — Карацуба (O(n^1.585)) выше порога 32 лимба,
  schoolbook ниже.
- **`fma`** — fused multiply-add `x·y + z` с одним округлением
  в конце.  Промежуточное произведение не округляется:
  на `x = 1 + 2^-80`, `y = 1 - 2^-80`, `z = -1` при `prec = 100`
  результат `-2^-160` точен, тогда как `mul + add` даёт `0`.
- **`trunc`, `floor`, `ceil`, `round`** — округление к целому
  (усечение к нулю, к -inf, к +inf, ties away from zero по C99).
- **`fmod`** — остаток `x - trunc(x/y)·y` со знаком делимого,
  с guard-точностью пропорциональной `x->exp - y->exp`.
- `sqrt`, `exp`, `log` — элементарные функции.
- **`log1p`, `expm1`** — точные `log(1+x)` и `exp(x) - 1`
  при малых `|x|` (guard-биты компенсируют сокращение).
- **`cbrt`** — кубический корень методом Ньютона с seed из `double`.
- **`pow`** — возведение в степень с семантикой C99 / MPFR,
  включая полный набор правил для `0`, `±inf`, `NaN`
  и знака нуля при нечётном целом показателе.
- **`pow_ui` / `pow_si`** — целочисленный показатель.  `pow_ui`
  использует **sliding window** для `n ≥ 2^16` (адаптивная
  ширина 3–5 бит), бинарное возведение ниже порога.
- **`root`** — корень n-й степени; `n = 1`, `2` обрабатываются
  напрямую, общий случай через `exp(log|x| / n)`.
- **`log2` / `log10`** — логарифмы по основаниям 2 и 10.
  `log2` использует reduction по степеням двойки и точен
  на `x = 2^m`.
- **`hypot`** — евклидова норма `√(x² + y²)` с масштабированием
  на `max(|x|, |y|)`.
- `pi`, `ln2`, `e` — публичные константы. **π считается через
  Borwein / Gauss-Legendre AGM** (квадратичная сходимость,
  ~12 итераций вместо ~900 членов Machin).
- `sin`, `cos`, `tan` — прямые тригонометрические функции.
- `atan`, `asin`, `acos` — обратные тригонометрические функции.
- **`sinh`, `cosh`, `tanh`, `asinh`, `acosh`, `atanh`** — все
  шесть гиперболических функций с корректной обработкой
  доменов, короткими замыканиями на малых и больших `|x|`
  и guard-битами против сокращения в `sinh`/`tanh`.
- **`*_with_pi`** — варианты всех шести тригонометрических функций,
  принимающие уже вычисленную π параметром.  Контракт:
  `pi->prec >= res->prec + 128 + E`, где `E = max(0, x->exp - 1)`.
- `print`, `print_d`, `fprint`, `fprint_d`, `get_str` — вывод:
  hex-мантисса, `double`-приближение, строка с заданным числом
  цифр и режимом округления в любом основании от 2 до 36.
  `fprint`/`fprint_d` принимают `FILE *`, `print`/`print_d` —
  их обёртки над `stdout`.
- Низкоуровневые утилиты: `get_bit`, `set_bit`, `msb`, `lsb`.
- **`s21_mpf_repl` — интерактивная утилита**: 26 унарных функций,
  7 бинарных, 1 тернарная (`fma`), три константы
  (`pi`, `ln2`, `e`), кэш π на текущую точность, вывод
  в base 10 / 16 / 8 / 2.
- `s21_mpf_bench` — микробенчмарк операций, включая сравнение
  тригонометрии с явной π и без; до `prec = 16384`.
- Unit-тесты в `src/test.c`: 61 группа, с автоподсчётом в финале;
  ULP-диагностика до `prec = 2048`.

### v1.25.0 (2026-10-17)

Sliding window в `pow_ui`.  Один коммит: 248 вставок / 13 удалений
в двух файлах.

- **`s21_mpf_pow_ui` для `n ≥ 2^16`** использует метод
  скользящего окна вместо бинарного возведения.  Ниже порога —
  бинарный путь: окно не окупает предвычисления.

  **Алгоритм:**

  - Таблица только нечётных степеней `g[i] = x^(2i+1)`,
    `i = 0..2^(k-1)-1`.  Нечётные — потому что каждое окно
    по построению заканчивается на 1.
  - Основной цикл идёт по битам `n` слева направо.  Нулевой
    бит — один квадрат.  Единичный — находим самое длинное
    окно (до `k` бит, оканчивающееся на 1), возводим результат
    в `2^win_len` и умножаем на `g[(w-1)/2]`.

  **Ширина окна** адаптивная:

  | диапазон `n` | `k` | таблица |
  |---|---|---|
  | `< 2^24` | 3 | 4 |
  | `< 2^32` (при 64-битном `unsigned long`) | 4 | 8 |
  | `≥ 2^32` | 5 | 16 |

  **Порог `n ≥ 2^16`.**  Ниже — бинарный путь.  Обоснование:
  предвычисления (таблица плюс bookkeeping) не окупаются
  на малых `n`.  Типичные вызовы `pow_ui` в библиотеке —
  парсинг точности, base-конверсия — работают на малых `n`
  и остаются на бинарном пути.

  **Память.**  Таблица — один `calloc` на
  `table_count · limbs_for_prec(wp)` лимбов, обёрнутый
  в массив `s21_mpf_t`, чьи `limbs` указывают внутрь общего
  буфера.  Одна аллокация вместо `table_count`.

- **Ожидаемый выигрыш.**  Для `n` с плотными единичными
  битами (`popcount(n) ≈ n/2`) число умножений падает
  с `~1.5·log₂(n)` до `~log₂(n) + 2^(k-1)`.  При `k = 4`
  и `log₂(n) = 32` — примерно с 48 до 40, около 17%.
  Для `n` — степеней двойки бинарный путь уже оптимален,
  и порог отправляет их именно туда.

- **Корректность.**  Спецзначения (`0`, `±inf`, `NaN`),
  `n = 0`, `n = 1` — короткие замыкания до основного пути.
  Знак результата — `sign_x & (n mod 2)`, как раньше.

- **Новая тест-группа `test_pow_ui_window`.**  Покрывает:

  - **границу порога**: `n = 65535` (бинарный) и `n = 65536`
    (окно) — оба дают `2^n` через `log2` round-trip;
  - **плотные биты**: `n = 131071` (17 единиц, `k = 3`),
    `n = 16777215` (24 единицы, `k = 3`),
    `n = 4294967295` (32 единицы, `k = 4`);
  - **степень двойки**: `n = 2^20` (порог отправляет
    в бинарный путь);
  - **отрицательное основание с чётным `n`**: `(-2)^65536`
    положительно;
  - **`pow_ui(-1, even/odd)`** = `+1` / `-1`;
  - **`pow_ui(1, 2^32)`** = `1`;
  - **согласованность**: `pow_ui(1.5, a)^2 ≈ pow_ui(1.5, 2a)`
    для `a = 100000`, обе стороны на окне, порог `1e-60`.

  Все случаи верифицированы через `log2` round-trip.
  Общее число групп: 55 → 56.

### v1.26.0 (2026-10-17)

Patch wave: семь мелких улучшений по результатам финального
code review.  Семантика существующего API не менялась, кроме
одного добавления (`fprint` / `fprint_d`).  Тестов 56 → 57.

- **`fix: div_raw`** — проверка `calloc` при OOM.  Раньше при
  нехватке памяти `base` был `NULL`, `div_knuth` писал через
  него.  Сигнатура и контракт не менялись; оба caller'а
  (`s21_mpf_div`, `s21_mpf_pow_si`) уже проверяли `rc`.

- **`fix: parse_special`** — явная проверка `strlen` перед
  чтением `s[0..7]`.  Прежний код полагался на short-circuit
  evaluation, что работало, но было хрупко при любой
  переделке (array-of-conditions, `strncasecmp`).

- **`fix: get_str_special`** — минимальный `bufsize` для `+inf`
  теперь 4, а не 5.  `"+inf"` — 4 байта, `"-inf"` — 5;
  прежняя проверка была асимметричной и отвергала валидный
  вызов `get_str(buf, 4, ...)` для `+inf`.

- **`feat: fprint / fprint_d`** — вывод в произвольный `FILE *`.
  `print` / `print_d` — тонкие обёртки над `stdout`.  `NULL`
  stream или `x` — no-op.  В `s21_mpf.h` добавлен
  `#include <stdio.h>` (неизбежно для `FILE *`, MPFR платит
  ту же цену).  Новая тест-группа `test_fprint` пишет в
  `tmpfile()` и проверяет точные байты для `+inf` и `42`.

- **`docs: s21_mpf_equal`** — уточнение семантики:
  bit-identical, не numeric.  `equal(1@64, 1@128) == 0`, хотя
  `cmp == 0`.  Для числового сравнения — `cmp`.

- **`docs: s21_mpf_set_str`** — trailing whitespace отвергается
  (`"42 "` → `-1`).  Намеренно, но неочевидно.

- **`docs: s21_mpf_init2`** — `calloc` не проверяется; OOM
  оставляет объект непригодным.  Задокументировано как
  precondition, не исправлено (сигнатура `void` → `int`
  прокаскадировала бы через всех caller'ов ради failure mode,
  который не воспроизводится ниже prec ~10⁷).

### v1.27.0 (2026-10-18)

Четыре фикса из «известных ограничений» финального code
review.  Все — только `fix:`, поведение API не меняется
на нормальных входах; два случая раньше возвращали мусор
(`pow` — теперь NaN, `sqrt` / `cbrt` — корректное значение).

- **`fix: set_ui / set_si / set_d`** — округление RNDN при
  `prec < 64` (для `unsigned long`) и `prec < 53` (для `double`).
  Раньше мантисса усекалась без округления:
  `set_ui(7, prec=2)` давал `6` вместо `8`, `set_d(1.75, prec=2)`
  — `1` вместо `2`.  Теперь при `prec >= 64` / `prec >= 53`
  работает старый путь (усечения нет, нормализация сдвигает
  только влево); при меньших — значение пишется на временный
  объект шириной источника и сужается через `set_round` с RNDN.
  `set_si` наследует фикс через `set_ui`.

- **`fix: set_str` hexfloat `p`-экспонента** — проверка
  переполнения на двух этапах: накопление `p_exp * 10 + digit`
  (return `-1` при выходе за `INT64_MAX`) и `M.exp += p_exp`
  через `__builtin_add_overflow`.  Раньше литерал вроде
  `"0x1p99999999999999999999"` вызывал UB.

- **`fix: pow`** — при `y.exp + log|x|.exp`, переполняющем
  `int64_t`, возвращается NaN.  Переполнение возможно только
  при ручной установке `y.exp` около `INT64_MAX`; для
  значений из `set_str` / `set_d` / `set_ui` / `pow_ui`
  ветка не достижима.

- **`fix: sqrt / cbrt`** — post-loop verification
  `|y² − a|/|a| < 2^-(prec−2)` (sqrt) и `|y³ − a|/|a| < 2^-(prec−2)`
  (cbrt).  Если проверка проходит — возвращается `y` (то же
  значение, что раньше); иначе NaN.  Первая версия
  использовала `cmp == 0` как признак сходимости, но для
  неполных кубов Newton естественно осциллирует между двумя
  bit-different / numeric-equal значениями, и `cbrt(5)` при
  некоторых prec возвращал NaN на валидном входе.  Verification
  по результату эту проблему устраняет.

Тестов 57 → 61.  Новые группы: `test_set_ui_si_d_rounding`,
`test_hexfloat_overflow`, `test_pow_exp_overflow`,
`test_newton_convergence`.

Порог в `sqrt`/`cbrt` verification в первой версии был перевёрнут
(`+prec-2` вместо `-(prec-2)`); исправлено в v1.27.1 — см. ниже.

### v1.27.1 (2026-10-18)

Один фикс: порог в post-loop verification `sqrt` / `cbrt`.
Сигнатура и семантика API не менялись.

- **`fix: sqrt / cbrt verification threshold`** — в v1.27.0
  проверка сравнивала `rel.exp` с `+prec − 2` вместо
  `−(prec − 2)`.  Поскольку Newton сходится к `~2^-wp`,
  `rel.exp` всегда глубоко отрицателен: неверный знак не
  отвергал корректных результатов, но и не ловил умеренных
  ошибок (`2^-100` при `prec = 256`), которые страховка
  должна была отсеивать.  Guard фактически не работал.
  Заменено на `rel.exp < -(int64_t)res->prec + 2` в обоих
  функциях.  Дополнительно обновлён комментарий к
  `S21_MPF_MAX_ARG_BITS`: константа используется не только
  в тригонометрическом reduction, но и в `log1p` / `expm1` /
  `fmod` / `*_with_pi`.

Тестов 61 (без изменений).  Все 61 группа проходит,
ULP-диагностика 0.0 по всем N = 32..2048.

## Сборка

Все команды запускаются из каталога `src/`:

```sh
cd src
make                     # статическая библиотека libs21_mpf.a
make test                # собрать и запустить unit-тесты
make repl                # интерактивная утилита s21_mpf_repl
make bench               # микробенчмарк s21_mpf_bench
make clang-format        # применить clang-format ко всем исходникам
make clang-format-check  # проверить форматирование (для CI, без правок)
make valgrind            # утечки памяти (memcheck)
make asan                # сборка с AddressSanitizer
make ubsan               # сборка с UndefinedBehaviorSanitizer
make gcov_report         # покрытие (lcov + genhtml)
make clean               # удаление артефактов
```

Альтернатива без `cd` — из корня проекта:

```sh
make -C src test
```

Компилятор: `gcc`, стандарт `-std=c11`, флаги `-Wall -Wextra -Werror -O2`.
Стиль кода задан в `.clang-format` (Google Style, отступ 2 пробела).

26 унарных функций сгруппированы по категориям, 7 бинарных,
1 тернарная (`fma`).  Тригонометрия использует кэш π: при первом
`sin 1.5` π считается на точность `256 + 128 = 384` бита,
при `sin 1e50` — на `256 + 128 + 166 = 550`.  Кэш
переиспользуется, если накопленная точность не меньше
запрошенной; при `setprec` сбрасывается.

Вывод в базах `hex` / `oct` / `bin` — команды с необязательным
числом: без него только переключают базу, с ним — переключают
и сразу печатают.  Для `oct` и `bin` формат `<sign>.<digits>p<exp>`
где `p` — степень текущего основания (`1.7p+1` для `oct` —
это `1.7₈ × 8¹`).  Для `hex` — полная мантисса через
`s21_mpf_print`.

## Как устроено внутри

### Представление числа

```c
typedef struct {
  uint64_t *limbs;   /* мантисса, little-endian, limbs[0] — младшие 64 бита */
  int64_t   exp;     /* x = (-1)^sign · mant · 2^(exp − prec) */
  uint32_t  prec;    /* точность в битах */
  int       sign;    /* 0 = +, 1 = − */
  int       kind;    /* ZERO / NORMAL / INF / NAN */
} s21_mpf_t;
```

**Инварианты для NORMAL:** MSB мантиссы на позиции `prec − 1`,
биты выше `prec` нулевые, значение `x = (−1)^sign · mant · 2^(exp − prec)`.

**Специальные значения:** `ZERO` (хранит знак −0), `INF` (±), `NAN`.

### Нормализация и смена точности

`s21_mpf_normalize` приводит мантиссу к инварианту MSB@prec−1.
Сдвиги — единые функции `s21_mpf_shift_left_into` / `s21_mpf_shift_right_into`.

`s21_mpf_set_prec` меняет точность на месте, сужение — RNDN.
`s21_mpf_set_prec_round` — то же, но с явным режимом округления.
Обе разделяют подпрограммы `mpf_sticky_below`, `mpf_round_up`,
`mpf_add_one`.

### Стековые временные объекты

Обёртка `s21_mpf_stack_t` содержит `s21_mpf_t` и буфер
`uint64_t[S21_MPF_STACK_LIMBS]` (32 лимба = 2048 бит).  Применяется
в `add`, `sub`, `div`, `pow`, гиперболических и в `*_raw`.

### Scratch-пространство `mul_raw`

`mul_raw` использует единый буфер `total = 2·l_wp + l_prod` лимбов.
Если `total ≤ S21_MPF_MUL_SCRATCH_LIMBS` (512 лимбов = 4 КБ) —
стековый массив и один `memset`; иначе — один `calloc(total)`.
`temp.limbs` служит приёмником `mul_mant`, отдельный `prod` не нужен.

### Карацуба в `mul_mant`

Для `n < S21_MPF_KARATSUBA_THRESHOLD = 32` умножение делается
schoolbook — двойной цикл по лимбам с накоплением через
`unsigned __int128`.  Для `n ≥ 32` мантиссы расщепляются по формуле:

```
a = a1·B^h + a0,   b = b1·B^h + b0,   B = 2^64, h = floor(n/2)
a·b = a1·b1·B^(2h) + [(a1+a0)(b1+b0) − a1·b1 − a0·b0]·B^h + a0·b0
```

Три рекурсивных умножения размера `n/2` вместо четырёх.  Сложность
O(n^1.585).

Scratch для текущего уровня и всей рекурсии — единый пул,
распределяемый в `s21_mpf_mul_mant_karatsuba` одним `malloc(10n + 256)`.

Публичный cross-check: `s21_mpf_mul_mant_schoolbook` экспонирован
во внутреннем API для тестов.  `test_mul_karatsuba_vs_schoolbook`
сверяет оба пути побитово на 12 размерах.

### Fused multiply-add

`fma(x, y, z) = x·y + z` с одним округлением в конце.
Рабочая точность `wp = 2·prec + 64`:

- произведение двух `prec`-битных мантисс точно укладывается
  в `2·prec` бит — `mul_raw` на `wp` не теряет ни одного бита;
- сумма с `z` добавляет максимум один бит (переполнение
  порядка) — `2·prec + 1 < wp`;
- финальное сужение `wp → prec` через `s21_mpf_set` —
  единственное округление за операцию.

Порядок обработки спецзначений:

1. **NaN-протокол** — любой NaN в `x`, `y` или `z` даёт NaN.
2. **inf в x или y** — если второй сомножитель ноль,
   `inf · 0 = NaN`.  Иначе — `±inf` со знаком
   `sign(x)·sign(y)`; если `z` — `inf` противоположного знака,
   получаем `NaN` (конфликт).
3. **inf в z** — результат `±inf` со знаком `z`.
4. **`x·y = ±0`** — результат равен `z`, с правилом знака
   нуля: если оба слагаемых `−0`, результат `−0`; иначе `+0`.
5. **Общий случай** — `mul_raw` на `wp`, `add_raw` на `wp`,
   одно финальное округление.

### Sliding window в `pow_ui`

Ниже `n = 2^16` — бинарное возведение.  Выше — sliding
window с адаптивной шириной `k ∈ {3, 4, 5}`.

**Почему не fixed window.**  В fixed window таблица содержит
все `2^k` степеней от `x^0` до `x^(2^k − 1)`, и на каждом
шаге основной цикл съедает ровно `k` бит.  Sliding window
хранит только нечётные степени (вдвое меньше таблицы)
и позволяет окну быть короче `k`, если младший бит
единичный — что снижает среднее число умножений.
Дополнительная сложность — один внутренний цикл
`while ((n >> l) & 1 == 0) l++` для поиска начала окна.

**Почему порог 2^16.**  При `n < 2^16` таблица (4–8 записей
по `prec/64 + 1` лимбов каждая) занимает память и время,
сравнимые с самим возведением.  Для типичных `n` из
библиотеки (парсинг точности, base-конверсия) работает
бинарный путь.

**Почему adaptive `k`.**  Ширина окна растёт с длиной `n`:
для 24-битных `n` достаточно `k = 3`, для 32+ битных — `k = 5`.
Большая таблица (16 записей) окупается только когда
основной цикл длинный.  Adaptive `k` даёт компромисс
без раздувания таблицы на коротких `n`.

**Память.**  Таблица — один `calloc` (`table_count · limbs_per`
лимбов).  Массив `s21_mpf_t` поверх того же буфера.
Одна аллокация вместо `table_count`.

### C99 hexfloat в `set_str`

Hexfloat-формат — стандартный способ точной записи `double`
(Annex F C99).  Формат:

```
[+-]? [0x|0X] hex_digits [. hex_digits]? [pP] [+-]? dec_digits
```

`p`-экспонента — десятичное число со знаком, задающее **степень
двойки**: `0x1.8p4` = `1.5 · 16^0 · 2^4`.  В отличие от
`e`-экспоненты (степень 10), `p` — степень 2.

Реализация:

1. Префикс `0x` / `0X` поглощается после знака, до `parse_special`.
2. Целая и дробная части — как в обычном `set_str`.
3. `p`-экспонента разбирается после дробной части, только
   для base 16.  Десятичные цифры с опциональным знаком.
4. Коррекция значения: `M.exp += p_exp`.  Умножение на `2^k`
   точное — мантисса не меняется, только экспонента.

Дробная часть масштабируется через `base^(-frac_digits)` как
обычно; `p`-экспонента добавляется поверх.

`p` в base ≠ 16 — не разделитель экспоненты.  В base ≥ 26
это цифра (и попадает в мантиссу); при меньших base — ошибка
хвоста.  Префикс `0x` / `0X` — только для base 16.  Для других
base `0x1` = `0 · base + x`, что не цифра, → ошибка.

`get_str` в base 16 hexfloat **не выдаёт** — только обычный
hex без `p`-экспоненты.  Симметрия с MPFR: там hexfloat —
входной формат, `mpfr_get_str` работает в обычных базах.

### Borwein AGM π

Формула (Gauss-Legendre / Borwein & Borwein, «Pi and the AGM»):

```
a₀ = 1, b₀ = 1/√2, t₀ = 1/4, p₀ = 1
Итерация: a_{n+1} = (aₙ + bₙ) / 2
          b_{n+1} = √(aₙ · bₙ)
          t_{n+1} = tₙ − pₙ · (aₙ − a_{n+1})²
          p_{n+1} = 2 · pₙ
Результат: π = (a + b)² / (4 · t)
```

Сходимость квадратичная: число правильных бит удваивается
за итерацию.  ~12 итераций покрывают `wp = 4160` — против ~900
членов ряда `atan(1/5)` и ~260 членов `atan(1/239)` в формуле
Мэчина.

Внутренняя точность — `wp + 64`, запас на накопление ошибки
в 12 итерациях.  Финальное `(a + b)² / (4t)` считается на
`wp + 64`, и только потом сужается до `wp` через `set_round`.
Прямое `div_raw` в целевую `pi` теряло бы старшие 64 бита
операндов (см. «История дефектов v1.15.0»).

`_machin`-версия сохранена во внутреннем API для cross-check.

### Argument reduction в тригонометрии

`reduce_2pi(r, a, pi, wp)` сводит `a` к `(-π, π]` через
`r = a − round(a / 2π) · 2π`.  Если `a ≈ 2^E`, вычитание двух
чисел порядка `2^E` сокращает `E` старших бит: точность падает
с `2^-wp` до `2^(E-wp)`.

Хелпер `trig_extra_bits(x)` возвращает `max(0, x->exp − 1)`.
Это значение добавляется к рабочей точности в `sin_impl`,
`cos_impl`, `tan` — и к контракту `*_with_pi`.  При
`E > S21_MPF_MAX_ARG_BITS = 10000` функция возвращает NaN.

### Знак нуля в `pow`

`pow(±0, y)` даёт `±0` или `±inf`; знак результата —
`sign_x & (y mod 2)`.  Это согласуется с `1 / (−0)³ = −inf`
и с IEEE 754 `pow(−0, 3) = −0`.  Чётность `y` определяется
одним битом мантиссы: для нормализованного `y` бит на позиции
`prec − exp` имеет вес `2⁰` в значении, поэтому именно он
и есть младший бит целой части.

### Сокращение в гиперболических

`sinh(x) = (e^x − e^−x) / 2`.  При малых `|x|` оба слагаемых
почти равны, разность — порядка `2x`.  Потеря точности
`log₂(1/|x|)` бит.  Хелпер `hyp_exp_pair` добавляет к рабочей
точности `guard = min(−exp(x), prec)`.

`cosh` этой проблемы не имеет: оба слагаемых одного знака,
сумма — порядка `e^x`, дополнительных guard-битов не требуется.

`tanh` использует ту же защиту, что `sinh` (числитель
подвержен сокращению, знаменатель — нет).

### Сокращение в `log1p` и `expm1`

`log1p(x) = log(1 + x)`.  При малых `|x|` сумма `1 + x` теряет
`log₂(1/|x|)` младших бит — они уходят в шум от сложения
чисел разных порядков.  Рабочая точность `prec + 64 + guard`,
где `guard = max(0, -x->exp)`.

`expm1(x) = exp(x) − 1`.  Тот же механизм: при малых `|x|`
`exp(x) ≈ 1 + x`, и вычитание единицы съедает старшие
`log₂(1/|x|)` бит результата.

Для `|x| < 2^(-prec/2)` хелпер возвращает `x` без вычислений —
поправка `x²/2` в этом случае меньше `2^(-prec)` и в целевую
точность не входит.

### Остаток `fmod` и guard-точность

`fmod(x, y) = x − trunc(x/y)·y`.  При `x/y ≈ 2^E` произведение
`trunc(x/y)·y` имеет тот же порядок, что `x`, и вычитание
теряет `E` бит.  Добавляем `E` к рабочей точности, потолок —
`S21_MPF_MAX_ARG_BITS` (как в тригонометрии и гиперболических).

### Основание в `set_str` / `get_str`

Обе функции обобщены на `base ∈ [2, 36]` через три хелпера:
`digit_value(c)` (символ → значение, `-1` вне алфавита),
`digit_char(d)` (значение → строчный символ) и
`is_digit_in_base(c, base)` (проверка «это цифра данной базы»).
Хелперы — статические, во внутренний API не экспонируются.

Парсинг экспоненты в `set_str`:

- для base 10 — `e` / `E`, десятичная степень;
- для base 16 — `p` / `P`, степень двойки (C99 hexfloat),
  плюс опциональный префикс `0x` / `0X`;
- для остальных base — экспонент нет, только цифры.

`get_str` использует `pow_base_mpf(res, base, k)` — обобщение
бывшего `pow10_mpf` — для масштабирования `y` к диапазону
`[1, base)`.

### Почему нет SIMD

`mul_mant_schoolbook` — единственный участок, где SIMD вообще
применим.  Карацуба и более высокоуровневая логика (`mul_raw`,
`div_raw`) работают с цепочками carry и рекурсией, которые
векторизуются плохо: переносы создают зависимости между
итерациями, а рекурсия — непредсказуемые обращения к памяти.

Schoolbook живёт при `n ≤ 32` (порог Карацубы).  Внутри `mul`
на `prec = 4096` это ~20% времени, на `prec = 16384` — около
25%.  SIMD дал бы ~1.5× на этой части, то есть **7–9% на `mul`
в целом** — ценой 300–500 строк платформозависимого кода,
двух реализаций (x86-64 + aarch64) и условной компиляции.  Для
учебного проекта это неоправданная сложность.

Реальные альтернативы для дальнейшего ускорения `mul` — ручной
ассемблер (`mulx`/`adcx`/`adox` в стиле GMP) или Schönhage-Strassen
FFT для `prec ≥ 10⁵`.  Обе за пределами текущего диапазона
и целей проекта.

### Алгоритмы по операциям

| Операция | Подход | Рабочая точность |
|---|---|---|
| `add`, `sub` | выравнивание по `exp`, сложение с carry / вычитание с borrow | `prec + 64` |
| `mul` | Карацуба выше 32 лимбов, schoolbook ниже | `prec + 64` |
| `div` | алгоритм D Кнута | `prec + 64` |
| `fma` | `mul_raw` на `2·prec + 64`, `add_raw`, одно округление | `2·prec + 64` |
| `sqrt` | метод Ньютона с seed из `double`, verification post-loop | `prec + 64` |
| `cbrt` | метод Ньютона с seed из `double`, verification post-loop | `prec + 64` |
| `exp` | ряд Тейлора после halving до `\|y\| ≤ 2^-5` | `prec + 64` |
| `expm1` | `exp(x) − 1` с guard-битами | `prec + 64 + max(0, −x->exp)` |
| `log` | atanh-ряд с `m = 5` sqrt reduction | `prec + 64` |
| `log1p` | `log(1 + x)` с guard-битами | `prec + 64 + max(0, −x->exp)` |
| `log2` | reduction `x = 2^k · y`, `k + ln(y)/ln 2` | `prec + 64` |
| `log10` | `log(x) / ln(10)` | `prec + 64` |
| `pow` | `exp(y · log\|x\|)`, знак отдельно, guard на exp overflow | `prec + 64` |
| `pow_ui` | sliding window (adaptive `k`) для `n ≥ 2^16`, бинарное ниже | `prec + 64` |
| `pow_si` | `pow_ui` + обращение через `div_raw` | `prec + 64` |
| `root` | `exp(log\|x\| / n)`, знак отдельно | `prec + 64` |
| `hypot` | `m · √((x/m)² + (y/m)²)`, `m = max(\|x\|, \|y\|)` | `prec + 64` |
| `trunc` | обнуление бит ниже `exp − 1` | `prec` |
| `floor`, `ceil` | `trunc` + сдвиг на 1 при наличии дроби | `prec + 64` |
| `round` | `trunc(x ± 0.5)` | `prec + 64` |
| `fmod` | `x − trunc(x/y) · y` с guard-битами | `prec + 64 + E`, `E = max(0, x->exp − y->exp)` |
| `set_str` | поразрядный разбор, `pow_base_mpf`; hexfloat (`0x…p…`) в base 16 — через сдвиг `exp`, guard на p-exp overflow | `prec + 64` |
| `get_str` | `n_digits · log₂(base) + 192` | — |
| `pi` | Borwein / Gauss-Legendre AGM | `prec + 64` |
| `ln2`, `e` | `2·atanh(1/3)` / `exp(1)` | `prec + 64` |
| `sin`, `cos` | reduction по `2π`, затем ряд | `prec + 64 + E` |
| `tan` | `sin(x) / cos(x)` | `prec + 64 + E` |
| `atan` | reduction + степенной ряд | `prec + 64` |
| `asin`, `acos` | через `atan` / `π/2 − asin` | `prec + 64` |
| `sinh`, `tanh` | `(e^{±x} − e^{∓x}) / 2`, `sinh/cosh` | `prec + 64 + guard` |
| `cosh` | `(e^x + e^{−x}) / 2` | `prec + 64` |
| `asinh`, `acosh` | `log(x + √(…))` | `prec + 64` |
| `atanh` | `½·log((1+x)/(1−x))` | `prec + 64` |
| `set_round` | RNDN / RNDZ / RNDU / RNDD | `dst->prec` |
| `set_prec`, `set_prec_round` | in-place | `prec` |

**Guard-биты `prec + 64`** защищают значащую часть результата.
Для `sin`/`cos`/`tan` добавляется `E` из-за сокращения в reduction;
для `sinh`/`tanh`, `log1p`/`expm1` — guard из-за сокращения
при малых `|x|`; для `fmod` — `E = x->exp − y->exp`;
для `fma` — полное `2·prec + 64` (произведение не округляется).

**Ленивое π** — вычисляется один раз на верхнем уровне и передаётся
в `_impl`-варианты.  Без глобального кэша в библиотеке.

**Knuth D в `div`** — O(n²) лимбовых умножений.

**Double seed в `sqrt` / `cbrt`** — ~7 итераций Newton из ~14
при `prec = 4096`.

**Post-loop verification в `sqrt` / `cbrt`** — проверка
`|y² − a|/|a|` (sqrt) или `|y³ − a|/|a|` (cbrt) против
`2^-(prec−2)`; при провале возвращается NaN.  Устойчива
к осцилляции Newton на неполных кубах.

**Sqrt reduction в `log`** — пять `sqrt` сокращают ряд с ~1300
до ~300 членов при `wp = 4160`.

**Карацуба в `mul`** — O(n^1.585) выше 32 лимбов.

**AGM в `pi`** — квадратичная сходимость, ~12 итераций на любой
`prec`.

### Тригонометрия с явной π

Публичные `sin`/`cos`/`tan`/... при каждом вызове считают π заново.
С v1.15.0 это уже не 12 мс, а ~2 мс при `prec = 4096`, но
по-прежнему доминирует: сам ряд `sin`/`cos` — ~3.4 мс.

Если в цикле много тригонометрических вызовов, π стоит
посчитать один раз:

```c
uint32_t prec = 4096;
s21_mpf_t pi;
s21_mpf_init2(&pi, prec + 128);
s21_mpf_pi(&pi);

s21_mpf_t x, r;
s21_mpf_init2(&x, prec);
s21_mpf_init2(&r, prec);

for (int i = 0; i < 1000; i++) {
  s21_mpf_set_d(&x, i * 0.001);
  s21_mpf_sin_with_pi(&r, &x, &pi);   // без пересчёта π
}
```

Шесть публичных функций `*_with_pi` — тонкие обёртки над
существующими `_impl`-вариантами.  Контракт:
`pi->prec >= res->prec + 128 + E`.  Меньшая точность π даёт -1;
при `E > S21_MPF_MAX_ARG_BITS` — NaN.

### I/O

**`set_str`** — посимвольный разбор с накоплением мантиссы
в `prec + 64` бит.  Работает в любом основании от 2 до 36;
в base 16 дополнительно принимает C99 hexfloat (`0x1.8p4`).
Финальное округление — RNDN.

**`get_str`** — оценка `E ≈ floor(log_base(x))`, масштабирование
через `pow_base_mpf`, нормализация в `[1, base)`, извлечение
цифр, округление RNDN / RNDZ / RNDU / RNDD.  Реализация
разбита на четыре подпрограммы: `get_str_special`,
`get_str_extract`, `get_str_should_round_up`, `get_str_round_up`.

комментарий к `S21_MPF_MAX_ARG_BITS` (константа используется
не только в тригонометрии).

(`0x0p4 = +0`, `-0x0p-4 = -0`); без `p` — обычный hex

ошибки (`0x`, `0xp4`, `0x1p`, `0x1p+`, `0x1p-`, `0x1pg`, `0xg`);
`p` в base 10 не является разделителем (`1p4` в base 10 → −1).

`test_hexfloat_overflow` — `"0x1p99999999999999999999"`
(накопление `p_exp` за `INT64_MAX`), `"0x1p9223372036854775807"`
(`M.exp + p_exp` переполняет `int64_t`), симметрично для
отрицательной `p`-экспоненты — все три возвращают `-1`.
`"0x1.8p4"` продолжает работать.  Проверяет защиту,
добавленную в v1.27.0.

`test_set_ui_si_d_rounding` — `set_ui(7, prec=2) = 8`,
`set_ui(5, prec=2) = 4` (ties-to-even), `set_ui(3, prec=2) = 3`
(точно), `set_si(-7, prec=2) = -8`, `set_d(1.25, prec=2) = 1`
(ties-to-even), `set_d(1.75, prec=2) = 2` (ties-to-even).
Проверяет RNDN-округление при `prec < 64` (ui/si) и
`prec < 53` (d), добавленное в v1.27.0.

### Теоретические оценки сложности

- `add`, `sub`, `cmp` — O(n);
- `mul` — O(n^1.585) (Карацуба), O(n²) ниже порога;
- `div` — O(n²);
- `fma` — стоимость `mul` + `add` на удвоенной точности;
- `sqrt`, `cbrt` — O(n²) на итерацию, O(log n) итераций,
  плюс O(n²) на post-loop verification;
- `exp`, `expm1` — O(n²·k), `k ≈ wp/5`;
- `log`, `log1p` — O(n²·k), `k ≈ wp/(2m+2)`, `m = 5`;
- `pow` — стоимость `exp` + `log` + `mul`;
- `pow_ui` — O(log n) умножений (sliding window); ниже `2^16`
  — бинарный O(log n) с константой ~1.5;
- `pow_si` — стоимость `pow_ui` + `div`;
- `root` — стоимость `exp` + `log` + `div`;
- `log2` — стоимость `log_unit_interval` + `ln2` + `div`;
- `log10` — стоимость `log` + `div`;
- `hypot` — стоимость `sqrt` + 2 `div` + 2 `mul`;
- `trunc` — O(n);
- `floor`, `ceil` — O(n);
- `round` — O(n);
- `fmod` — стоимость `div` + `mul` + `sub` с guard-точностью;
- `set_str` — O(digits) `mul_raw` + O(digits) `add_raw` + одно `pow_base_mpf`; hexfloat-экспонента — O(1);
- `get_str` — O(n_digits) делений;
- `pi` — O(M(n)·log n) — 12 итераций AGM, каждая — `sqrt` + `mul`;
- `sin`/`cos` — O(n²·k) по ряду + π;
- `sinh`/`cosh`/`tanh` — стоимость одного `exp` (плюс `div` для `tanh`);
- `asinh`/`acosh`/`atanh` — стоимость `log` + `sqrt`.

Проверка по семи принципам Дейкстры и их следствиям.  Состояние
после v1.27.1.

**Принципы:**

| № | Принцип | Статус |
|---|---|---|
| 1 | Отказ от `goto` | ⚠️ два осознанных исключения: `cmd_binary` / `cmd_ternary` в REPL (cleanup при нескольких ресурсах) |
| 2 | Три базовые конструкции | ✅ |
| 3 | Произвольная вложенность базовых конструкций | ✅ |
| 4 | Логически целостные фрагменты выносятся в подпрограммы | ✅ |
| 5 | Каждая группа инструкций — блок | ✅ |
| 6 | Один вход, один выход | ⚠️ арифметика — ✅, спецзначения — ранние `return` |
| 7 | Разработка сверху вниз | ✅ |

**Следствия:**

| № | Следствие | Статус |
|---|---|---|
| 1 | Запрет глобальных переменных | ✅ (в REPL — статическое состояние утилиты) |
| 2 | Не более одного выхода из функции | ⚠️ см. принцип 6 |
| 3 | Не более одного выхода из цикла | ✅ |
| 4 | Вложенность блоков ≤ 4 | ✅ (максимум — 2) |
| 5 | Размер функций 40–50 строк | ⚠️ `div_knuth` (~55), `mul_mant_rec` (~50), `cmd_ternary` (~85), `pow_ui` (~120), `set_str` (~130 из-за hexfloat); на границе — `get_str`, `fma`, `process_line`, `pow`, `root`, `hypot`, `cbrt`, `sqrt` (с post-loop verification), `exp`, `atan_impl`, `cos_impl`, `tan_impl`, `pi_agm_iterate` |

**Комментарии к ⚠️:**

- **`goto cleanup`** — два случая, оба в REPL, оба про
  освобождение нескольких ресурсов (`x`, `y`, `z`, `r`)
  при трёх точках отказа.  Альтернатива — три уровня
  вложенных `if` либо дублирование освобождения в каждой
  ветке.  Выбран `goto` ради читаемости.  В библиотеке
  `goto` не используется нигде.
- **Pre-checks** — защита от некорректного вызова.
- **Ранние `return 0` на спецзначениях** — `*_special`-паттерн
  не подходит для функций, чьи `_impl`-варианты ожидают только
  `NORMAL`; `pow`, `pow_ui`, `pow_si`, `root`, `hypot`,
  `log1p`, `expm1`, `fmod`, `fma` и гиперболические следуют
  тому же принципу.
- **`div_knuth`**, **`mul_mant_rec`** — структурно сложные функции
  с внутренними фазами алгоритма.  Каждая из них уже разбита
  настолько, насколько позволяет структура алгоритма.
- **`cmd_ternary`** (~85 строк) — зеркальная копия `cmd_binary`
  с добавлением одного аргумента.  Разбивать не имеет смысла:
  логика линейная, каждое расширение — это один и тот же
  трёхшаговый паттерн (ask, parse, dispatch).
- **`pow_ui`** (~120 строк) — две реализации в одной функции:
  бинарный путь (25 строк) и sliding window (85 строк).
  Кандидат на вынос в `pow_ui_binary` / `pow_ui_window`,
  но оба варианта используют общую подготовку (`n = 0`, `n = 1`,
  спецзначения, `odd_n`), и вынос создаст дублирование этой
  подготовки либо потребует передавать `wp` через параметр.
  Оставлено как есть.
- **`cbrt`** — цикл Newton плюс post-loop verification,
  на границе 50 строк.
- **`sqrt`** — цикл Newton плюс post-loop verification,
  на границе 50 строк.
- **`process_line`** (REPL) — расширился до ~30 команд
  в 26 унарных, 7 бинарных и 1 тернарной таблицах.
  Разбит линейно, вложенность 1.
- **`set_str`** вырос до ~130 строк после добавления hexfloat.
  Два цикла разбора, ветки валидации, три экспоненты
  (hexfloat `p`, десятичная `e`, префикс `0x`).  Кандидат
  на вынос `accumulate_digit(M, d, base, wp)` и
  `parse_hexfloat_exp` / `parse_dec_exp`.

## Roadmap на будущее

Проект достиг законченного состояния.  Дальнейшие пункты —
инженерные оптимизации с плохим соотношением выигрыша к цене;
оставлены здесь для полноты анализа.

- **Hexfloat на выходе.**  Сейчас `get_str` в base 16 выдаёт
  обычный hex без `p`-экспоненты.  Вывод в C99-формате
  (`0x1.921fb54442d18p+1`) — отдельная функция, MPFR
  её тоже не предоставляет.  Отложено.

- **SIMD в `mul_mant_schoolbook` — рассмотрено, не окупается.**
  Schoolbook-путь вызывается только при `n ≤ 32` (ниже порога
  Карацубы).  Внутренний цикл — 32×32 = 1024 умножения,
  ~3000 тактов.  SIMD-версия через 32-битный split (SSE2,
  baseline x86-64) дала бы schoolbook-пути ~1.5×, что на
  полном `mul` составляет **7–9%**.  Цена: 300–500 строк
  платформозависимого кода, две реализации (x86-64 + aarch64),
  условная компиляция по уровню SIMD.  Экономика не сходится.

  Реальный путь к ускорению `mul_mant_schoolbook` — **не SIMD,
  а ручной ассемблер** (`mulx` + `adcx` + `adox` из BMI2/ADX,
  Haswell+ 2013+).  Это подход GMP, даёт ~2.5× на schoolbook
  против чистого C.  Но: только x86-64, только свежие CPU,
  теряется портативность.  Для учебного проекта это за пределами
  поставленных целей.

- **Toom-Cook 3-way** — пересмотреть только после появления
  ассемблерной версии `mul_mant_schoolbook`.  На чистом C11
  crossover выше 300 лимбов, что за пределами нашей рабочей
  области.  Реализация сохранена в истории (коммиты `9780945`
  и `d4e5f01`), откат — `4bb3947` и `9bd58b5`.  Замеры — в блоке
  v1.16.0.

- **Sasaki-Kanada AGM-log.**  Формула
  `ln x = π / AGM(θ₂²(1/x), θ₃²(1/x))` из статьи 1982 года.
  Не окупается на текущей архитектуре: нужна π внутри, а даже
  с AGM-π она стоит ~2 мс при `prec = 4096` против 3.2 мс всего
  `log`.  Может стать выгодной после ускорения π.

- **Binary splitting для atanh-ряда.**  Не окупается для mpf-аргументов:
  требует повышения точности до `wp + log₂(N!)`, что перевешивает
  выигрыш от divide-and-conquer.  Имеет смысл только для рациональных
  аргументов с малым числителем/знаменателем (например, для ln2,
  π через Machin), где у нас уже есть быстрые реализации.

## Мотивация

В `s21_math` мы делали `math.h` с точностью `long double`.
Предел — эффективная точность ~226 бит.  `s21_mpfr` снимает
это ограничение: точность задаётся пользователем от 2 бит
до миллионов.  Это позволяет вычислять `sin(1e10)` с точностью
`2^-1000`, реализовывать произвольную точность для криптографии
(RSA, ECC), экспериментировать без потери контроля над
форматом числа.
