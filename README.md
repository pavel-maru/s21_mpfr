# s21_mpfr

> **Status:** 🟢 **v1.7.0 (2026-10-11).**
> Библиотека чисел с плавающей точкой произвольной точности на C11.
> Вдохновлено [MPFR](https://www.mpfr.org/), но реализуется с нуля
> в учебных целях.

Собственная реализация библиотеки чисел с плавающей точкой
произвольной точности. Продолжение проекта
[s21_math](https://github.com/pavel-maru/s21_math), где мы
упирались в ограничения `long double` (80/128/64 бит).
Здесь эти границы убираются полностью — точность задаёт
пользователь.

## Что уже готово

- Тип `s21_mpf_t` — число произвольной точности (мантисса от 2 бит).
- `init`, `init2`, `clear` — управление жизненным циклом.
- `set_prec` — in-place смена точности с сохранением значения
  (расширение — точно, сужение — округление RNDN).
- `set_ui`, `set_si`, `set_d`, `set_str` — присваивание из базовых
  типов и из десятичных строк.
- `set_zero`, `set_inf`, `set_nan` — специальные значения.
- `set`, `set_round` — присваивание с режимами округления
  RNDN / RNDZ / RNDU / RNDD.
- `cmp`, `cmp_abs`, `equal`, `zero_p`, `integer_p` — сравнения,
  включая корректную работу на числах разных точностей.
- `add`, `sub`, `mul`, `div`, `neg`, `abs` — базовая арифметика,
  корректная при любой точности (включая некратные 64).
- `sqrt`, `exp`, `log` — элементарные функции.
- `pi` — константа π (формула Мэчина).
- `sin`, `cos`, `tan` — прямые тригонометрические функции.
- `atan`, `asin`, `acos` — обратные тригонометрические функции.
- `print`, `print_d`, `get_str` — вывод: hex-мантисса, `double`-приближение,
  десятичная строка с заданным числом цифр и режимом округления.
- Низкоуровневые утилиты: `get_bit`, `set_bit`, `msb`, `lsb`.
- `s21_mpf_repl` — интерактивная утилита для экспериментов
  с функциями библиотеки (REPL: команда, аргументы, точность).
- `s21_mpf_bench` — микробенчмарк операций на разных точностях.
- Unit-тесты в `src/test.c`: 31 группа, покрывают все публичные
  функции, режимы округления, граничные значения, малые и
  некратные точности, I/O round-trip, ULP-диагностику.

### v1.7.0 (2026-10-11)

I/O: парсинг и форматирование десятичных строк.

- **`s21_mpf_set_str`** — разбор строки в mpf. Формат:
  `[+-]?(digits[.digits]?|.digits)([eE][+-]?digits)?`.
  Спецзначения `inf`, `infinity`, `nan` (регистронезависимо).
  Рабочая точность `prec + 64`, финальное округление RNDN.
- **`s21_mpf_get_str`** — печать mpf в десятичную строку с явным
  числом значащих цифр и режимом округления. Конвенция MPFR:
  `buf` = знак + `n_digits` цифр без точки, `*exp_out` = позиция
  десятичной точки, так что `value ≈ 0.DDDD... × 10^exp_out`.
- **REPL: dec-вывод через `get_str`**. Раньше ограничение было
  17 значащими цифрами (`double`), теперь — сколько угодно до 1000.
  Команда `dec <n>` устанавливает число цифр.
- **REPL: аргументы через `set_str`**. Ввод больше не проходит через
  `double`, так что `3.14` — это ровно 3.14, а не double-приближение.
- **REPL: команда `show <num>`** и приём голого числа (`3.14` ==
  `show 3.14`). Удобно для проверки парсинга.
- 31-я группа тестов: `test_set_str`, `test_get_str` — включая
  round-trip `get_str → set_str` для 3.14.

## Сборка

Все команды запускаются из каталога `src/`:

```sh
cd src
make                     # статическая библиотека libs21_mpf.a
make test                # собрать и запустить unit-тесты
make repl                # интерактивная утилита s21_mpf_repl
make bench               # микробенчмарк s21_mpf_bench
make clang-format        # применить clang-format ко всем исходникам
make clang-format-check  # проверить форматирование (для CI, без правок)
make valgrind            # утечки памяти (memcheck)
make asan                # сборка с AddressSanitizer
make ubsan               # сборка с UndefinedBehaviorSanitizer
make gcov_report         # покрытие (lcov + genhtml)
make clean               # удаление артефактов
```

Альтернатива без `cd` — из корня проекта:

```sh
make -C src test
```

Компилятор: `gcc`, стандарт `-std=c11`, флаги `-Wall -Wextra -Werror -O2`.
Стиль кода задан в `.clang-format` (Google Style, отступ 2 пробела).

## Как устроено внутри

### Представление числа

```c
typedef struct {
  uint64_t *limbs;   /* мантисса, little-endian, limbs[0] — младшие 64 бита */
  int64_t   exp;     /* x = (-1)^sign · mant · 2^(exp − prec) */
  uint32_t  prec;    /* точность в битах */
  int       sign;    /* 0 = +, 1 = − */
  int       kind;    /* ZERO / NORMAL / INF / NAN */
} s21_mpf_t;
```

**Инварианты для NORMAL:** MSB мантиссы на позиции `prec − 1`,
биты выше `prec` нулевые, значение `x = (−1)^sign · mant · 2^(exp − prec)`.

**Специальные значения:** `ZERO` (хранит знак −0), `INF` (±), `NAN`.

### Нормализация и смена точности

`s21_mpf_normalize` приводит мантиссу к инварианту MSB@prec−1.
Сдвиги — единые функции `s21_mpf_shift_left_into` / `s21_mpf_shift_right_into`
с раздельно заданными `dst_count` / `src_count`.

`s21_mpf_set_prec` меняет точность на месте, сохраняя значение:
расширение — точно, сужение — RNDN.

### Стековые временные объекты

Обёртка `s21_mpf_stack_t` содержит `s21_mpf_t` и буфер
`uint64_t[S21_MPF_STACK_LIMBS]` (32 лимба = 2048 бит). Если рабочая
точность влезает — `limbs` указывает на стек; иначе `stack_init`
вызывает `calloc`. Освобождать через `s21_mpf_stack_clear`, не через
`s21_mpf_clear` (последний сделает `free()` от указателя на стек).

Применяется в `add`, `sub`, `div` (все три временных) и в `add_raw` /
`div_raw` для вспомогательных буферов.

### Алгоритмы по операциям

| Операция | Подход | Рабочая точность |
|---|---|---|
| `add`, `sub` | выравнивание по `exp`, сложение с carry / вычитание с borrow; для разных знаков — через `cmp_abs` | `prec + 64` |
| `mul` | школьное умножение `mul_mant` (O(n²)); финальное округление RNDN | `prec + 64` |
| `div` | алгоритм D Кнута: нормализация делителя, `n+1` итераций с оценкой `q̂`, уточнением и add-back | `prec + 64` |
| `sqrt` | метод Ньютона `x_{n+1} = (x_n + a/x_n)/2` | `prec + 64` |
| `exp` | ряд Тейлора с halving | `prec + 64` |
| `log` | atanh-ряд с reduction к `[1, 2)` | `prec + 64` |
| `pi` | формула Мэчина | `prec + 64` |
| `sin`, `cos` | reduction по `2π` через `reduce_2pi`, затем ряд | `prec + 64` |
| `tan` | `sin(x) / cos(x)`; одна π на вызов | `prec + 64` |
| `atan` | reduction + степенной ряд; π только для `|x| > 1` | `prec + 64` |
| `asin` | `atan(x / √(1 − x²))` | `prec + 64` |
| `acos` | `π/2 − asin(x)` | `prec + 64` |
| `set_round` | RNDN / RNDZ / RNDU / RNDD | `dst->prec` |
| `set_prec` | in-place смена точности | `prec` |

**Guard-биты `prec + 64`** защищают значащую часть результата
от накопленной ошибки округления.

**Ленивое π** — вычисляется один раз на верхнем уровне и передаётся
в `_impl`-варианты. Без глобального кэша: он нарушает принцип «нет
глобальных переменных» и порождает проблемы thread-safety.

**Knuth D в `div`** — O(n²) лимбовых умножений вместо O(prec²)
битовых сдвигов старой реализации.

### I/O

**`set_str`** — посимвольный разбор целой и дробной частей
с накоплением мантиссы в `prec + 64` бит. Экспонента
применяется как `M · 10^E` (бинарное возведение в степень,
`log₂(|E|)` умножений). Финальное округление — RNDN.

**`get_str`** — оценка `E ≈ floor(log₁₀(x))`, масштабирование
`y = |x| / 10^E` на рабочей точности `n_digits · 4 + 192` бит,
нормализация в `[1, 10)`, извлечение цифр `d = floor(y)`.
Решение об округлении из остатка `y ∈ [0, 10)` — RNDN (ties-to-even),
RNDZ, RNDU, RNDD. Знак обрабатывается отдельно: цикл
нормализации `while (y < 1) y *= 10` для отрицательного `y`
не завершился бы.

**v1.0.0**: `cmp_abs` через `double` на разных `prec`;

**v1.1.0**: `cmp(0, x<0)`; `abs(-0)`; `set_d` субнормальных;
знак `tan` при `cos=0`; `sub_raw` через `add_raw`;
сдвиги с раздельными `dst_count`/`src_count`.

## Точность и тестирование

### ULP-метрика

`test_ulp_diagnostics` — для каждой функции сравниваются результаты
при `prec = N` и `prec = 2N`. Gap в ULP младшей точности. Все
результаты — 0.0, что подтверждает достаточность guard-битов
и отсутствие систематической потери точности.

### Бенчмарк

`s21_mpf_bench` — измерения после оптимизаций v1.6.0
(x86-64, gcc -O2, best of 3):

| op | prec=64 | prec=256 | prec=1024 | prec=4096 |
|---|---|---|---|---|
| `add`  | 136 ns | 167 ns | 358 ns | 1.25 μs |
| `sub`  | 181 ns | 218 ns | 386 ns | 1.22 μs |
| `mul`  | 225 ns | 359 ns | 951 ns | 7.84 μs |
| `div`  | 256 ns | 439 ns | 1.76 μs | 12.4 μs |
| `sqrt` | 1.57 μs | 3.34 μs | 16.0 μs | 151 μs |
| `exp`  | 11.1 μs | 34.8 μs | 261 μs | 3.13 ms |
| `log`  | 12.9 μs | 42.9 μs | 409 μs | 9.44 ms |
| `sin`  | 28.6 μs | 89.5 μs | 772 μs | 16.1 ms |

`div`/`mul` теперь 1.1–2.0× — эффект Knuth D. `add`/`sub` при малых
`prec` больше не доминируются аллокациями (v1.6.0).

### Теоретические оценки сложности

- `add`, `sub`, `cmp` — O(n) по числу лимбов;
- `mul` — O(n²), школьный алгоритм;
- `div` — O(n²) лимбовых умножений;
- `sqrt` — O(n²) на итерацию, итераций O(log n);
- трансцендентные — O(n²·k), где `k` — число членов ряда.

## Чек-лист структурного программирования

Проверка по семи принципам Дейкстры и их следствиям. Состояние
после рефакторинга v1.7.0.

**Принципы:**

| № | Принцип | Статус |
|---|---|---|
| 1 | Отказ от `goto` | ✅ |
| 2 | Три базовые конструкции | ✅ |
| 3 | Произвольная вложенность базовых конструкций | ✅ |
| 4 | Логически целостные фрагменты выносятся в подпрограммы | ✅ |
| 5 | Каждая группа инструкций — блок | ✅ |
| 6 | Один вход, один выход | ⚠️ арифметика — ✅, тригонометрические обёртки — ранние `return` на спецзначениях |
| 7 | Разработка сверху вниз | ✅ |

**Следствия:**

| № | Следствие | Статус |
|---|---|---|
| 1 | Запрет глобальных переменных | ✅ |
| 2 | Не более одного выхода из функции | ⚠️ см. принцип 6 |
| 3 | Не более одного выхода из цикла | ✅ |
| 4 | Вложенность блоков ≤ 4 | ✅ (максимум — 2) |
| 5 | Размер функций 40–50 строк | ⚠️ `add_raw` (~70), `div_knuth` (~55), `get_str` (~85); на границе — `set_str`, `sqrt`, `exp`, `atan_impl`, `cos_impl` |

**Комментарии к ⚠️:**

- **Pre-checks** (`check_binary` / `check_unary`) — защита
  от некорректного вызова, а не выход из основной логики.
- **Ранние `return 0` на спецзначениях в тригонометрии** —
  то же самое, но `*_special`-паттерн не подходит, потому что
  `_impl`-функции ожидают только `NORMAL`.
- **`add_raw`** и **`div_knuth`** — две структурно сложные
  функции. Дробление первой отложено до оптимизации сложения;
  вторая расставляет фазы D3/D4/D6 комментариями.
- **`get_str`** — длинная линейная функция без глубокой вложенности.
  Дробление на три подпрограммы (оценка `E`, нормализация, извлечение
  цифр) возможно, но сейчас не критично: логика читается
  сверху вниз по шагам алгоритма.

## Roadmap на будущее

- **`mul_raw` со стеком.** Внутри `mul_raw` произведение занимает
  `2·wp` лимбов, что не влезает в стековый буфер при `prec > 512`.
  Отдельный дизайн (scratch-space или двухуровневая схема).
- **`set_prec_round(x, prec, rnd)`** — смена точности с явным
  режимом округления. Сейчас `set_prec` всегда RNDN.
- **Карацуба / Toom-Cook** для `mul`, **Ньютон** для `div` поверх
  быстрого `mul` — при `prec > 4096` школьный алгоритм становится
  узким местом.
- **Тест субнормального `set_d`** — минимальный денормализованный
  `5e-324` не проверен явно.
- **Публичные константы** `ln2`, `e` как отдельные символы API.
- **Произвольные основания** (`base = 2, 8, 16`) в `set_str` / `get_str`.

## Мотивация

В `s21_math` мы делали `math.h` с точностью `long double`.
Финальная версия (v1.0.0) решала argument reduction problem
даже на Apple Silicon через double-double. Но предел всё равно
оставался: эффективная точность максимум ~226 бит.

`s21_mpfr` снимает это ограничение: точность задаётся
пользователем от 2 бит до миллионов. Это позволяет:

- Вычислять `sin(1e10)` с точностью `2^-1000`, а не `2^-16`.
- Реализовывать произвольную точность для криптографии
  (RSA, ECC) — числа длиной 2048, 4096 бит.
- Экспериментировать с произвольной точностью без потери
  контроля над форматом числа.
