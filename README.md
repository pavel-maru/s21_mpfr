# s21_mpfr

> **Status:** 🟢 **v1.10.0 (2026-10-12).**
> Библиотека чисел с плавающей точкой произвольной точности на C11.
> Вдохновлено [MPFR](https://www.mpfr.org/), но реализуется с нуля
> в учебных целях.

Собственная реализация библиотеки чисел с плавающей точкой
произвольной точности. Продолжение проекта
[s21_math](https://github.com/pavel-maru/s21_math), где мы
упирались в ограничения `long double` (80/128/64 бит).
Здесь эти границы убираются полностью — точность задаёт
пользователь.

## Что уже готово

- Тип `s21_mpf_t` — число произвольной точности (мантисса от 2 бит).
- `init`, `init2`, `clear` — управление жизненным циклом.
- `set_prec` — in-place смена точности с сохранением значения
  (расширение — точно, сужение — округление RNDN).
- `set_ui`, `set_si`, `set_d`, `set_str` — присваивание из базовых
  типов и из десятичных строк.
- `set_zero`, `set_inf`, `set_nan` — специальные значения.
- `set`, `set_round` — присваивание с режимами округления
  RNDN / RNDZ / RNDU / RNDD.
- `cmp`, `cmp_abs`, `equal`, `zero_p`, `integer_p` — сравнения,
  включая корректную работу на числах разных точностей.
- `add`, `sub`, `mul`, `div`, `neg`, `abs` — базовая арифметика,
  корректная при любой точности (включая некратные 64).
- `sqrt`, `exp`, `log` — элементарные функции.
- `pi` — константа π (формула Мэчина).
- `sin`, `cos`, `tan` — прямые тригонометрические функции.
- `atan`, `asin`, `acos` — обратные тригонометрические функции.
- **`*_with_pi`** — варианты всех шести тригонометрических функций,
  принимающие уже вычисленную π параметром. Позволяет не считать π
  на каждый вызов в цикле (при prec = 4096 экономия до 4.2× для
  `sin`/`cos` и 2.6× для `tan`).
- `print`, `print_d`, `get_str` — вывод: hex-мантисса, `double`-приближение,
  десятичная строка с заданным числом цифр и режимом округления.
- Низкоуровневые утилиты: `get_bit`, `set_bit`, `msb`, `lsb`.
- `s21_mpf_repl` — интерактивная утилита с кэшем π на текущую
  точность.
- `s21_mpf_bench` — микробенчмарк операций, включая сравнение
  тригонометрии с явной π и без.
- Unit-тесты в `src/test.c`: 35 групп, с автоподсчётом в финале;
  ULP-диагностика до `prec = 2048`.

### v1.10.0 (2026-10-12)

Улучшенный argument reduction для `exp`/`log` и критический
фикс `exp`, найденный попутно.

- **`log`: m = 5 sqrt reduction.** К `y ∈ [1, 2)` применяется
  5 итераций `sqrt` перед построением `z = (y-1)/(y+1)`. Ряд
  `atanh(z)` сходится за ~`wp / (2m+2)` членов вместо
  ~`wp / log₂(9)`: для `wp = 4160` это ~300 vs ~1300.
  Стоимость 5 sqrt (~500 μs с v1.9.0 double seed) окупается
  шестикратно.
- **`exp`: halving до `|y| ≤ 2^-5`** вместо `|y| < 1`. Ряд
  Тейлора сокращается с ~`wp` до ~`wp/5` членов. Четыре
  дополнительных квадрата (по одной `mul`) дешевле ~200
  сэкономленных членов.
- **Фикс: обрезание ряда `exp`.** Внутри `exp` был жёсткий cap
  в 300 членов, заложенный с первой версии. При `prec ≥ ~3000`
  ряд для `exp(1.5)` требует больше — он молча обрезался,
  и `exp` возвращал результат с точностью ниже обещанной.
  Халвинг обнажил проблему. Заменено на `max_terms = wp + 10`,
  что при `wp = 4160` даёт 4170 итераций — 5× запас над
  теоретической границей `wp/5`. Естественное условие сходимости
  (`term.exp < sum.exp - wp - 4`) останавливает цикл на ~305.
- **`test_exp_log_extremes`**: `log(exp(±100))`, `log(10^10)`,
  `log(10^-10)`, `log(1 + 2^-50)`, `exp(a)·exp(-a) = 1`.
- **`test_ulp_diagnostics` расширен до N = 2048** — семь
  столбцов `N = 32, 64, 128, 256, 512, 1024, 2048`. Закрывает
  класс багов, где ошибка проявляется только при больших `prec`.

Ускорение по бенчмарку:

|---|---|---|---|---|
| `exp` было | 10.7 μs | 31.3 μs | 264 μs | 3.14 ms (усечён) |
| `exp` стало | 8.34 μs | 21.9 μs | 181 μs | 3.55 ms (правильно) |

## Как устроено внутри

### Представление числа

```c
typedef struct {
  uint64_t *limbs;   /* мантисса, little-endian, limbs[0] — младшие 64 бита */
  int64_t   exp;     /* x = (-1)^sign · mant · 2^(exp − prec) */
  uint32_t  prec;    /* точность в битах */
  int       sign;    /* 0 = +, 1 = − */
  int       kind;    /* ZERO / NORMAL / INF / NAN */
} s21_mpf_t;
```

**Инварианты для NORMAL:** MSB мантиссы на позиции `prec − 1`,
биты выше `prec` нулевые, значение `x = (−1)^sign · mant · 2^(exp − prec)`.

**Специальные значения:** `ZERO` (хранит знак −0), `INF` (±), `NAN`.

### Нормализация и смена точности

`s21_mpf_normalize` приводит мантиссу к инварианту MSB@prec−1.
Сдвиги — единые функции `s21_mpf_shift_left_into` / `s21_mpf_shift_right_into`
с раздельно заданными `dst_count` / `src_count`.

`s21_mpf_set_prec` меняет точность на месте, сохраняя значение:
расширение — точно, сужение — RNDN.

### Стековые временные объекты

Обёртка `s21_mpf_stack_t` содержит `s21_mpf_t` и буфер
`uint64_t[S21_MPF_STACK_LIMBS]` (32 лимба = 2048 бит). Если рабочая
точность влезает — `limbs` указывает на стек; иначе `stack_init`
вызывает `calloc`. Освобождать через `s21_mpf_stack_clear`, не через
`s21_mpf_clear` (последний сделает `free()` от указателя на стек).

Применяется в `add`, `sub`, `div` (все три временных) и в `add_raw` /
`div_raw` для вспомогательных буферов.

### Алгоритмы по операциям

| Операция | Подход | Рабочая точность |
|---|---|---|
| `add`, `sub` | выравнивание по `exp`, сложение с carry / вычитание с borrow; для разных знаков — через `cmp_abs` | `prec + 64` |
| `mul` | школьное умножение `mul_mant` (O(n²)); финальное округление RNDN | `prec + 64` |
| `div` | алгоритм D Кнута: нормализация делителя, `n+1` итераций с оценкой `q̂`, уточнением и add-back | `prec + 64` |
| `sqrt` | метод Ньютона `x_{n+1} = (x_n + a/x_n)/2` с seed из `double` (~53 правильных бита) | `prec + 64` |
| `exp` | ряд Тейлора после halving до `|y| ≤ 2^-5`; `s` финальных квадратов | `prec + 64` |
| `log` | atanh-ряд: `m = 5` sqrt-итераций к `y ∈ [1, 2)`, затем `z = (y^(1/2^m)-1)/(y^(1/2^m)+1)` | `prec + 64` |
| `pi` | формула Мэчина | `prec + 64` |
| `sin`, `cos` | reduction по `2π` через `reduce_2pi`, затем ряд | `prec + 64` |
| `tan` | `sin(x) / cos(x)`; одна π на вызов | `prec + 64` |
| `atan` | reduction + степенной ряд; π только для `|x| > 1` | `prec + 64` |
| `asin` | `atan(x / √(1 − x²))` | `prec + 64` |
| `acos` | `π/2 − asin(x)` | `prec + 64` |
| `set_round` | RNDN / RNDZ / RNDU / RNDD | `dst->prec` |
| `set_prec` | in-place смена точности | `prec` |

**Guard-биты `prec + 64`** защищают значащую часть результата
от накопленной ошибки округления.

**Ленивое π** — вычисляется один раз на верхнем уровне и передаётся
в `_impl`-варианты. Без глобального кэша в библиотеке: он нарушает
принцип «нет глобальных переменных» и порождает проблемы
thread-safety.

**Knuth D в `div`** — O(n²) лимбовых умножений вместо O(prec²)
битовых сдвигов старой реализации.

**Double seed в `sqrt`** — 64 старших бита мантиссы → `m_norm ∈ [1, 2)`,
`√(m_norm · 2^rem)` через libm, масштабирование `ldexp(half)`.
Экономит ~7 итераций Newton из ~14 при `prec = 4096`. Fallback
на `2^(exp/2 + 1)` при экстремальных `exp`.

**Sqrt reduction в `log`** — пять `sqrt` от `y ∈ [1, 2)` приводят
аргумент `atanh` к `z ≈ (y-1)/(2^m · (y+1))`. Ряд сходится за
~`wp / (2m+2)` членов вместо ~`wp / log₂(9)`. Пять `sqrt` при
`prec = 4096` стоят ~500 μs, экономят ~6 ms.

### Тригонометрия с явной π

Публичные `sin`/`cos`/`tan`/`atan`/`asin`/`acos` при каждом вызове
считают π заново. Для `prec = 4096` это порядка **12 мс** —
формула Мэчина требует ~900 членов ряда `atan(1/5)` и ~260 членов
`atan(1/239)`, каждый член — `mul_raw` на 65 лимбах. Сам ряд
sin/cos на той же точности занимает ~4 мс, то есть π доминирует
в три раза.

Если в цикле делается много тригонометрических вызовов, π стоит
посчитать один раз:

```c
uint32_t prec = 4096;
s21_mpf_t pi;
s21_mpf_init2(&pi, prec + 128);
s21_mpf_pi(&pi);

s21_mpf_t x, r;
s21_mpf_init2(&x, prec);
s21_mpf_init2(&r, prec);

for (int i = 0; i < 1000; i++) {
  s21_mpf_set_d(&x, i * 0.001);
  s21_mpf_sin_with_pi(&r, &x, &pi);   // без пересчёта π
}
```

Шесть публичных функций `*_with_pi` — тонкие обёртки над
существующими `_impl`-вариантами. Контракт: `pi->prec >= res->prec + 128`.
Меньшая точность π даёт -1.

REPL использует эту схему прозрачно: тригонометрические команды
держат одну π на текущую точность, сбрасывая кэш при `setprec`.

### I/O

**`set_str`** — посимвольный разбор целой и дробной частей
с накоплением мантиссы в `prec + 64` бит. Экспонента
применяется как `M · 10^E` (бинарное возведение в степень,
`log₂(|E|)` умножений). Финальное округление — RNDN.

**`get_str`** — оценка `E ≈ floor(log₁₀(x))`, масштабирование
`y = |x| / 10^E` на рабочей точности `n_digits · 4 + 192` бит,
нормализация в `[1, 10)`, извлечение цифр `d = floor(y)`.
Решение об округлении из остатка `y ∈ [0, 10)` — RNDN (ties-to-even),
RNDZ, RNDU, RNDD. Знак обрабатывается отдельно.

### История исправленных дефектов

**v1.0.0**: `cmp_abs` через `double` на разных `prec`;
`mul` при `prec`, не кратных 32.

**v1.1.0**: `cmp(0, x<0)`; `abs(-0)`; `set_d` субнормальных;
знак `tan` при `cos=0`; `sub_raw` через `add_raw`;
сдвиги с раздельными `dst_count`/`src_count`.

**v1.2.0**: только структурный рефакторинг.

**v1.3.0**: `set_prec` меняла `prec` без пересчёта `exp`;
`mpf_add_one` не обрабатывала перенос в бит `prec` при `prec % 64 != 0`.

**v1.4.0**: `print_d` переполнялась в `+inf` при `prec > 1024`.

**v1.5.0 – v1.9.0**: без дефектов.

**v1.10.0**: **обрезание ряда `exp`**. Жёсткий cap `n < 300`
в цикле Тейлора, заложенный с первой версии. При `prec ≥ ~3000`
ряд требует больше членов и молча обрезался: `exp` возвращал
результат с точностью ниже обещанной, без индикации ошибки.
Обнаружено при попытке ускорить `exp` через halving — новый
режим просто перестал показывать ускорение на `prec = 4096`.
Заменено на `max_terms = wp + 10`. Тест `test_ulp_diagnostics`
расширен до `N = 2048`, чтобы класс подобных багов ловился
автоматически.

## Точность и тестирование

### ULP-метрика

`test_ulp_diagnostics` — для каждой функции сравниваются результаты
при `prec = N` и `prec = 2N`. Gap в ULP младшей точности. Прогон
идёт по семи точностям `N = 32, 64, 128, 256, 512, 1024, 2048`.
Все результаты — 0.0, что подтверждает достаточность guard-битов.

Расширение до N = 2048 добавлено в v1.10.0 после того, как
баг с обрезанием ряда `exp` показал, что верхняя граница 256
не покрывает режимы, где ряд сходится медленнее.

### Бенчмарк

`s21_mpf_bench` — измерения после оптимизаций v1.10.0
(x86-64, gcc -O2, best of 3). Строки «with pi» — тригонометрия
с явно переданной π (`*_with_pi`).

| op | prec=64 | prec=256 | prec=1024 | prec=4096 |
|---|---|---|---|---|
| `add`  | 135 ns | 166 ns | 367 ns | 1.10 μs |
| `sub`  | 182 ns | 221 ns | 384 ns | 1.25 μs |
| `mul`  | 242 ns | 325 ns | 982 ns | 7.67 μs |
| `div`  | 252 ns | 475 ns | 1.60 μs | 12.4 μs |
| `sqrt` | 836 ns | 1.80 μs | 9.52 μs | 107 μs |
| `exp`  | 8.34 μs | 21.9 μs | 181 μs | 3.55 ms |
| `log`  | 10.2 μs | 25.2 μs | 187 μs | 3.52 ms |
| `sin`  | 27.3 μs | 86.1 μs | 777 μs | 16.3 ms |
| `sin*` | 10.1 μs | 29.8 μs | 234 μs | 3.84 ms |
| `cos`  | 27.6 μs | 86.4 μs | 777 μs | 16.3 ms |
| `cos*` | 10.5 μs | 30.4 μs | 237 μs | 3.84 ms |
| `tan`  | 60.1 μs | 153 μs | 1.13 ms | 20.8 ms |
| `tan*` | 31.9 μs | 78.9 μs | 522 μs | 7.96 ms |

`*` — с явной π (`*_with_pi`). Экономия: `sin`/`cos` — до **4.2×**
при 4096; `tan` — до **2.6×** (одна π уже была, экономится только
сама π).

`sqrt` после v1.9.0: **2.05×** при prec=64, **2.02×** при 256,
**1.60×** при 1024, **1.50×** при 4096.

`exp`/`log` после v1.10.0: **1.3–1.5×** для `exp`, **1.2–2.7×**
для `log` в зависимости от точности (эффект растёт с `prec`,
потому что растёт доля сокращённого ряда).

REPL использует ту же схему прозрачно: тригонометрические команды
кэшируют одну π на текущую точность.

### Теоретические оценки сложности

- `add`, `sub`, `cmp` — O(n) по числу лимбов;
- `mul` — O(n²), школьный алгоритм;
- `div` — O(n²) лимбовых умножений;
- `sqrt` — O(n²) на итерацию, итераций O(log n) (сокращается
  вдвое с seed из `double`);
- `exp` — O(n²·k), где `k ≈ wp/5` после halving;
- `log` — O(n²·k), где `k ≈ wp/(2m+2)` после sqrt reduction
  (`m = 5`);
- `sin`/`cos` — O(n²·k) по ряду плюс π Мэчина, если не передан
  через `*_with_pi`.

- **Pre-checks** — защита от некорректного вызова, не выход

  фазы D3/D4/D6 комментариями.
- **`get_str`** — длинная линейная функция, дробление возможно,
  но не критично.

## Roadmap на будущее

- **`mul_raw` со стеком.** Внутри `mul_raw` произведение занимает
  `2·wp` лимбов, что не влезает в стековый буфер при `prec > 512`.
  Отдельный дизайн (scratch-space или двухуровневая схема).
- **Карацуба / Toom-Cook** для `mul`, **Ньютон** для `div` поверх
  быстрого `mul` — при `prec > 4096` школьный алгоритм становится
  узким местом. Карацуба начинает выигрывать примерно с
  `n ≈ 32–64` лимба (`prec ≈ 2048–4096`).
- **`set_prec_round(x, prec, rnd)`** — смена точности с явным
  режимом округления. Сейчас `set_prec` всегда RNDN.
- **Тест субнормального `set_d`** — минимальный денормализованный
  `5e-324` не проверен явно.
- **Публичные константы** `ln2`, `e` как отдельные символы API.
- **Произвольные основания** (`base = 2, 8, 16`) в `set_str` / `get_str`.

## Мотивация

В `s21_math` мы делали `math.h` с точностью `long double`.
Финальная версия (v1.0.0) решала argument reduction problem
даже на Apple Silicon через double-double. Но предел всё равно
оставался: эффективная точность максимум ~226 бит.

`s21_mpfr` снимает это ограничение: точность задаётся
пользователем от 2 бит до миллионов. Это позволяет:

- Вычислять `sin(1e10)` с точностью `2^-1000`, а не `2^-16`.
- Реализовывать произвольную точность для криптографии
  (RSA, ECC) — числа длиной 2048, 4096 бит.
- Экспериментировать с произвольной точностью без потери
  контроля над форматом числа.
