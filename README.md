# s21_mpfr

> **Status:** 🟢 **v1.2.0 (2026-10-07).**
> Библиотека чисел с плавающей точкой произвольной точности на C11.
> Вдохновлено [MPFR](https://www.mpfr.org/), но реализуется с нуля
> в учебных целях.

Собственная реализация библиотеки чисел с плавающей точкой
произвольной точности. Продолжение проекта
[s21_math](https://github.com/pavel-maru/s21_math), где мы
упирались в ограничения `long double` (80/128/64 бит).
Здесь эти границы убираются полностью — точность задаёт
пользователь.

## Что уже готово

- Тип `s21_mpf_t` — число произвольной точности (мантисса от 2 бит).
- `init`, `init2`, `clear` — управление жизненным циклом.
- `set_prec` — in-place смена точности с сохранением значения
  (расширение — точно, сужение — округление RNDN).
- `set_ui`, `set_si`, `set_d` — присваивание из базовых типов.
- `set_zero`, `set_inf`, `set_nan` — специальные значения.
- `set`, `set_round` — присваивание с режимами округления
  RNDN / RNDZ / RNDU / RNDD.
- `cmp`, `cmp_abs`, `equal`, `zero_p`, `integer_p` — сравнения,
  включая корректную работу на числах разных точностей.
- `add`, `sub`, `mul`, `div`, `neg`, `abs` — базовая арифметика,
  корректная при любой точности (включая некратные 64).
- `sqrt`, `exp`, `log` — элементарные функции.
- `pi` — константа π (формула Мэчина).
- `sin`, `cos`, `tan` — прямые тригонометрические функции.
- `atan`, `asin`, `acos` — обратные тригонометрические функции.
- `print`, `print_d` — отладочная печать.
- Низкоуровневые утилиты: `get_bit`, `set_bit`, `msb`, `lsb`.
- Unit-тесты в `src/test.c`: 26 групп, покрывают все публичные
  функции, режимы округления, граничные значения, малые точности
  (2, 3, 5, 8), точности, не кратные 32 (33, 100, 130), не кратные 64
  при `set_round`, смешанные точности в одной операции, регрессию
  на границу лимбов при сужении точности и in-place смену точности.

## Что нового

### v1.1.0 (2026-10-07)

Публичный API изменился только в части `set_prec` — остальное
внутреннее.

  значения. Расширение — точно, сужение — округление RNDN.
  Спецзначения (ZERO / INF / NAN) переносятся как есть.
  Сигнатура сменилась на `int s21_mpf_set_prec(...)` (0 / −1).
  Раньше функция меняла `prec` без пересчёта `exp` и нарушала
  инвариант MSB@prec−1. Добавлена группа `test_set_prec`
  из восьми подпунктов: expand, narrow exact, narrow round,
  narrow to 2.0 (переполнение мантиссы), same prec, clamp,
  special, NULL.
- Расширена группа `test_set_round`: добавлен случай `prec`,
  не кратного 64, где проверяется корректность маскирования
  старшего неполного лимба после округления.
- Ленивое вычисление π: `sin`/`cos`/`atan`/`asin` принимают π
  параметром через внутренние `_impl`-варианты. `tan` считает π
  один раз на оба `sin` и `cos`, `acos` — один раз на весь вызов,
  `atan` при `|x| ≤ 1` не считает π вовсе.
- Единые реализации сдвигов влево/вправо в `s21_mpf_bits.c` вместо
  четырёх копий логики (были в `normalize`, `set_round`, `arith`,
  и как отдельная функция).
- `set_round` разбит на три подпрограммы: `mpf_sticky_below`,
  `mpf_round_up`, `mpf_add_one`.
- Единая серия `s21_mpf_atan_series(alternating)` вместо двух
  почти идентичных функций для `atanh` и `atan`.
- Хелперы `check_binary` / `check_unary` — вместо 13 копий проверок
  `NULL` и совпадения `prec`.
- Диспетчер специальных значений в `add`/`mul`/`div` вынесен в
  `*_special`-подпрограммы; публичные функции теперь имеют один
  основной выход.
- Исправления: `cmp(0, x<0)`, `abs(-0)`, `set_d` для субнормальных
  `double`, знак `tan` при `cos = 0`, `sub_raw` через делегирование
  в `add_raw`.
- Исправление сдвигов мантиссы при смене точности: раздельные
  `dst_count` / `src_count` вместо одного счётчика. Добавлен
  регрессионный тест `test_round_narrow_across_limb_boundary`.

### v1.2.0 (2026-10-07)

Продолжение структурного рефакторинга. Публичный API не менялся.

- `div_raw` разбит на пять подпрограмм: `rem_shift_left_one`,
  `rem_ge_y`, `rem_sub_y`, `quotient_has_overflow`,
  `quotient_shift_right_one`. Сама функция сократилась с ~85 до
  ~35 строк, вложенность — с 4 до 2. Каскад специальных значений
  полностью переехал в `div_special`, поэтому `div_raw` теперь
  работает только с `NORMAL` — контракт совпадает с `add_raw`
  и `sub_raw`.
- `log` разбит на три подпрограммы: `log_reduce_to_unit`,
  `log_unit_interval`, `log_compute_ln2`. Главная функция стала
  линейной последовательностью: каскад спецзначений → reduction
  → ряд для `[1, 2)` → опциональная добавка `k·ln2`. Также убран
  промежуточный буфер `a` (не несший смысла) и fast-path `a == 1`
  (общий путь и так даёт 0).
- `mul_raw` больше не проверяет специальные значения: это
  дублировало `mul_special`, а все внешние вызовы `mul_raw`
  (из `func.c`) приходят с `NORMAL`-операндами. Контракт
  `*_raw`-функций стал единым: `NORMAL` на входе, спецзначения
  обрабатываются публичными обёртками и `*_special`.
- Общий reduction по `2π` для `sin` и `cos` вынесен в
  `reduce_2pi(r, a, pi, wp)`. Обе `_impl`-функции сократились
  ещё на ~15 строк каждая; логика вычитания кратного `2π`
  живёт в одном месте.

Все команды запускаются из каталога `src/`:

```sh
cd src
make                     # статическая библиотека libs21_mpf.a
make test                # собрать и запустить unit-тесты
make clang-format        # применить clang-format ко всем исходникам

make ubsan               # сборка с UndefinedBehaviorSanitizer
make gcov_report         # покрытие (lcov + genhtml)
make clean               # удаление артефактов
```

Альтернатива без `cd` — из корня проекта:

```sh
make -C src test
```

Компилятор: `gcc`, стандарт `-std=c11`, флаги `-Wall -Wextra -Werror -O2`.
Стиль кода задан в `.clang-format` (Google Style, отступ 2 пробела).

## Как устроено внутри

### Представление числа

```c
typedef struct {
  uint64_t *limbs;   /* мантисса, little-endian, limbs[0] — младшие 64 бита */
  int64_t   exp;     /* x = (-1)^sign · mant · 2^(exp − prec) */
  uint32_t  prec;    /* точность в битах */
  int       sign;    /* 0 = +, 1 = − */
  int       kind;    /* ZERO / NORMAL / INF / NAN */
} s21_mpf_t;
```

**Инварианты для NORMAL:**

- старший значащий бит мантиссы стоит на позиции `prec − 1`;
- биты выше `prec` нулевые;
- значение `x = (−1)^sign · mant · 2^(exp − prec)`,
  где `mant = Σ limbs[i] · 2^(64i)`.

Значение и `exp` связаны неотрывно: изменение `prec` меняет вес каждого
бита мантиссы, поэтому любая операция, меняющая `prec`, обязана
пересчитать `exp`.

**Специальные значения** (`kind`): `ZERO` (отдельно хранит знак −0),
`INF` (±), `NAN`. Все арифметические функции первым делом их обрабатывают
и только потом переходят к работе с `NORMAL`.

### Нормализация

Центральная операция — `s21_mpf_normalize`. Приводит мантиссу
к инварианту MSB@prec−1 сдвигом влево или вправо и корректирует `exp`
на ту же величину. Сдвиги реализованы едиными функциями
`s21_mpf_shift_left_into` / `s21_mpf_shift_right_into`, которые
принимают раздельно `dst_count` и `src_count` — это позволяет
использовать их и при смене точности, когда количество лимбов
источника и приёмника различается.

### Смена точности

`s21_mpf_set_prec` меняет точность на месте, сохраняя значение.
Опорный инвариант: `exp` не зависит от `prec` и равен «показателю
MSB + 1», то есть вес старшего бита мантиссы — это `2^(exp − 1)`.
При смене `prec` мантисса сдвигается так, чтобы этот вес не
изменился, а `exp` остаётся на месте (кроме случая округления
вверх через границу, где `exp` инкрементируется).

- Расширение — точное (сдвиг влево).
- Сужение — округление RNDN (через `mpf_sticky_below` +
  `mpf_round_up` + `mpf_add_one`).
- Спецзначения (`ZERO` / `INF` / `NAN`) переносятся как есть:
  перераспределяется только буфер, поля не трогаются.

### Алгоритмы по операциям

| Операция | Подход | Рабочая точность |
|---|---|---|
| `add`, `sub` | выравнивание по `exp` через `shift_right_into`, сложение с carry / вычитание с borrow; для разных знаков — через `cmp_abs` | `prec + 64` |
| `mul` | школьное умножение `mul_mant` (O(n²)); произведение умещается в `2·wp` бит | `2 · prec` |
| `div` | побитовое длинное деление; частное накапливается бит за битом, остаток сравнивается с делителем | `prec + 64` |
| `sqrt` | метод Ньютона `x_{n+1} = (x_n + a/x_n)/2`; начальное приближение `2^(half_exp+1)` | `prec + 64` |
| `exp` | ряд Тейлора с halving: `y = a/2^s`, `s` подобрано так, чтобы `|y| < 1`, затем `s` раз квадрат | `prec + 64` |
| `log` | atanh-ряд: `y = a / 2^k` (нормализация `a` к `[1, 2)`), `log(a) = log(y) + k·ln2`; `ln2` через `atanh(1/3)` | `prec + 64` |
| `pi` | формула Мэчина: `π = 16·atan(1/5) − 4·atan(1/239)`, `atan` через степенной ряд | `prec + 64` |
| `sin`, `cos` | reduction по модулю `2π` через `reduce_2pi`, затем степенной ряд; π передаётся через `_impl` | `prec + 64` |
| `tan` | `sin(x) / cos(x)`; одна π на весь вызов | `prec + 64` |
| `atan` | для `|x| > 1`: `π/2 − atan(1/x)`; для средних `x` — reduction `a := a/(1 + √(1+a²))` до 16 раз, затем ряд. Для `|x| ≤ 1` π не вычисляется | `prec + 64` |
| `asin` | `atan(x / √(1 − x²))`; π прокидывается через цепочку | `prec + 64` |
| `acos` | `π/2 − asin(x)`; одна π на весь вызов | `prec + 64` |
| `set_round` | округление мантиссы при смене `prec`; режимы RNDN (ties-to-even), RNDZ, RNDU, RNDD | `dst->prec` |
| `set_prec` | in-place смена `prec`; расширение — точно, сужение — RNDN | `prec` |

**Почему везде `prec + 64` (или `2 · prec`)?** Каждая операция выполняется
с запасом в 64 бита, чтобы накопленная ошибка округления в младших битах
не проникала в значащую часть результата после финального `set()` в `res`.
Это тот же принцип, что в MPFR — «guard bits».

**Ленивое π.** Изначально каждая тригонометрическая функция считала π
с нуля. Это не дублирование кода, но дублирование вычислений: в `tan`
π считалась дважды (для `sin` и `cos`), в `acos(x)` при `|x| < 1` —
тоже дважды (своя и в `asin → atan`), в `atan(x)` при `|x| ≤ 1` — вообще
была не нужна. Теперь π вычисляется один раз на верхнем уровне и
передаётся вниз через `_impl`-варианты. От глобального кэша сознательно
отказались: он нарушает принцип «нет глобальных переменных» и порождает
проблемы thread-safety и привязки к `prec`.

### История исправленных дефектов

**v1.0.0.** Оба дефекта корректности, найденных при расширении тестов,
были связаны с длиной хвоста в операциях:

- `cmp_abs` при разных `prec` собирала мантиссы в `double` (53 бита) и
  теряла младшие биты. Исправлено на побитовое сравнение с padding.
- `mul` при `prec`, не кратных 32, работала в `temp.prec = 2·wcount·64`
  (граница лимба) вместо реальной точности `2·wp`. Экспонента уезжала
  на `(2·wcount·64 − 2·wp)` бит. Исправлено на `temp.prec = 2·wp`.

**v1.1.0.** Дефекты, найденные при структурном ревью:

- `cmp(0, отрицательное)` возвращал `-1` вместо `+1`: в функции не было
  ветки для сравнения нуля с ненулевым числом, и знак обрабатывался
  через `cmp_abs`.
- `abs(-0)` не сбрасывал знак: `set` копировал `ZERO` как есть, а
  обнуление знака было только для `NORMAL` и `INF`.
- `set_d` для субнормальных `double` давал значение в 2 раза меньше:
  вес LSB мантиссы субнормала — `2^(-1074)`, что соответствует
  `exp_d − 53 = −1074`, то есть `exp_d = −1021`, а не `−1022`.
- `tan` при `cos = 0` всегда возвращал `+inf`, включая случай `x = −π/2`.
  Теперь знак берётся из `sin`.
- `sub_raw` жёстко ставила `sign = 0` после вычитания, что давало
  неверный результат при разных знаках операндов. Функция не
  использовалась публично, но была потенциальной ловушкой. Теперь
  делегирует `add_raw` через `neg_raw`.
- Сдвиги мантиссы использовали один счётчик для `dst` и `src`. При
  сужении точности (`set_round`), когда источник длиннее приёмника,
  старшие лимбы источника терялись. Проявлялось как «1 + 2 при prec=2
  равно 0». Исправлено разделением `dst_count` и `src_count`;
  добавлен регрессионный тест `test_round_narrow_across_limb_boundary`.
- `set_prec` меняла `prec` без пересчёта `exp` и нарушала инвариант
  MSB@prec−1 (число становилось нулём при сужении). Переписана
  как in-place с сохранением значения и RNDN при сужении.

**v1.2.0.** Дефектов не найдено — релиз состоит только из
структурного рефакторинга. Публичное поведение не менялось,
тесты (26/26) остались зелёными на каждом шаге.

### Разложение по файлам

- `s21_mpf_core.c` — жизненный цикл, присваивание, `normalize`,
  `set_round` (через `mpf_sticky_below` / `mpf_round_up` /
  `mpf_add_one`), `set_prec` (in-place, RNDN при сужении).
- `s21_mpf_bits.c` — низкоуровневые битовые операции над мантиссой,
  включая единые сдвиги.
- `s21_mpf_cmp.c` — сравнения (в том числе при разных `prec`).
- `s21_mpf_arith.c` — арифметика: `add` / `sub` / `mul` / `div` /
  `neg` / `abs`, внутренние `*_special`-диспетчеры спецзначений и
  пять подпрограмм длинного деления (`rem_shift_left_one`,
  `rem_ge_y`, `rem_sub_y`, `quotient_has_overflow`,
  `quotient_shift_right_one`).
- `s21_mpf_func.c` — элементарные функции и тригонометрия;
  `_impl`-варианты для передачи π; подпрограммы логарифма
  (`log_reduce_to_unit` / `log_unit_interval` /
  `log_compute_ln2`); общий `reduce_2pi`.
- `s21_mpf_print.c` — отладочный вывод.
- `s21_mpf_internal.h` — внутренний API (`*_raw`, `div_small`,
  сдвиги, `check_*`, `_impl`), не видимый пользователю библиотеки.

## Точность и тестирование

### Что проверяется сейчас

Каждая функция покрыта unit-тестами: базовые значения, границы,
специальные случаи (NaN, ±inf, ±0), режимы округления. Пороговые значения
в тестах заданы через `double`-константы (например, `1e-14`), что
достаточно для проверки поведения, но **не** даёт метрики «насколько
результат точен в ULP».

### Планируется: ULP-метрика

Из `s21_math` мы унаследовали идею измерять отклонение результата
в ULP (units in the last place). Там эталоном была `libm`; здесь
эталона нет, но его можно эмулировать **самосогласованно**:

1. Вычислить `f(x)` при `prec = N` и при `prec = 2·N`.
2. Привести оба к общему виду (например, к целочисленной мантиссе
   фиксированной длины).
3. Разница в ULP = `|result_N − result_2N| / ulp`.

Если при удвоении точности расхождение падает экспоненциально — алгоритм
сходится. Если стоит на месте — это предел реализации (недостаточная
рабочая точность, обрезание ряда, накопление ошибок). Метрика покажет
это без внешних зависимостей.

Опционально можно добавить сравнение с MPFR, если он установлен
(`pkg-config --exists mpfr`), но это уже за пределами v1.x.

### Планируется: бенчмарк

Замеры времени на разных `prec` (64, 256, 1024, 4096 бит) для каждой
операции. Теоретические оценки сложности:

- `add`, `sub`, `cmp` — O(n) по числу лимбов;
- `mul` — O(n²), школьный алгоритм;
- `div` — O(n²) (побитовое деление, `2·prec` итераций по `n` лимбов);
- `sqrt` — O(n²) на итерацию, итераций O(log n);
- `exp`, `log`, `sin`, `cos`, `atan` — O(n²·k) на член ряда, `k` членов
  до сходимости, зависит от reduction.

Бенчмарк покажет, где упираемся в теоретический предел, а где помогает
ранний выход.

| 4 | Логически целостные фрагменты выносятся в подпрограммы | ✅ |
| 5 | Каждая группа инструкций — блок | ✅ |
| 6 | Один вход, один выход | ⚠️ арифметика — ✅, тригонометрические обёртки — ранние `return` на спецзначениях |
| 7 | Разработка сверху вниз | ✅ |

**Следствия:**

| № | Следствие | Статус |
|---|---|---|
| 1 | Запрет глобальных переменных | ✅ |
| 2 | Не более одного выхода из функции | ⚠️ см. принцип 6 |
| 3 | Не более одного выхода из цикла | ✅ |
| 4 | Вложенность блоков ≤ 4 | ✅ (максимум — 2) |
| 5 | Размер функций 40–50 строк | ⚠️ `add_raw` (~70); на границе — `sqrt`, `exp`, `atan_impl`, `cos_impl` |

**Что изменилось по сравнению с v1.0.0:**

- **Принцип 4** — было формально ✅ при наличии четырёх копий сдвига и
  двух копий серии `atanh`/`atan`; теперь действительно ✅. Единые
  `shift_left_into` / `shift_right_into`, единая `atan_series`,
  хелперы `check_binary` / `check_unary`, `*_special`-диспетчеры,
  `reduce_2pi`, пять подпрограмм деления, три подпрограммы `log`.
- **Принцип 6 / следствие 2** — арифметические функции (`add`, `sub`,
  `mul`, `div`) приведены к паттерну «pre-check + `*_special` + один
  `return 0`». Тригонометрические обёртки (`sin`, `cos`, `tan`, `atan`,
  `asin`, `acos`) по-прежнему обрабатывают спецзначения ранними
  `return 0` — по природе это то же самое ветвление по типу аргумента
  до основной логики, что и pre-check, но строго по Дейкстре это
  выходы из основной логики.
- **Следствие 3** — во всех циклах рядов (`exp`, `sin`, `cos`,
  `atan_series`) два `break` объединены в один через `||`.
- **Следствие 4** — было 4 в `div_raw`; после выноса пяти
  подпрограмм деления максимальная вложенность по проекту — 2.
- **Следствие 5** — большинство функций уложились в норму за счёт
  выноса подпрограмм. Например: `set_round` (110 → 45),
  `normalize` (65 → 30), `add` (48 → 22), `div_raw` (85 → 35),
  `log` (75 → 45), `sin_impl`/`cos_impl` (были ~60, стали ~45).
  Единственная функция, превышающая порог, — `add_raw` (~70 строк):
  она держит две ветки (одного и разных знаков) в одном теле.
  Дальнейшее дробление — отдельная задача, см. roadmap.

**Комментарии к ⚠️:**

- **Pre-checks** (`check_binary` / `check_unary`) — допустимое
  исключение по самому Дейкстре: это защита от некорректного вызова,
  а не дополнительный выход из основной логики.
- **Ранние `return 0` на спецзначениях в тригонометрии** — та же
  природа, что pre-checks, но применить к ним `*_special`-паттерн
  мешает то, что `_impl`-функции ожидают только `NORMAL` и не умеют
  работать с `NaN`/`Inf`/`Zero`. Вынести их в отдельные подпрограммы
  можно, но это усложнит публичные обёртки без выигрыша в читаемости.
- **`add_raw`** — оставшаяся длинная функция. Разбить её на
  `add_same_sign` и `add_diff_sign` технически просто, но обе ветки
  разделяют подготовку (выравнивание по `exp`, `calloc` для сдвинутого
  операнда, `free`), а вынесение этой подготовки в отдельную
  подпрограмму сделает код менее линейным. Отложено до момента, когда
  появится реальная причина трогать `add_raw` — например, оптимизация
  сложения.

## Roadmap на будущее

Известные ограничения, не вошедшие в v1.2.0:

- **`set_prec` с явным режимом округления** — сейчас `set_prec`
  всегда использует RNDN при сужении. Отдельный
  `set_prec_round(x, prec, rnd)` даст доступ к RNDZ/RNDU/RNDD,
  как у `set_round`. Само `set_prec` уже переписано (v1.1.0)
  и корректно сохраняет значение.
- **Производительность**: `div_raw` побитовый, `sqrt` — итерации
  Ньютона с фиксированным верхним пределом, `mul` — «школьное»
  умножение O(n²). Позже — нарезка на лимбы и продвинутые
  алгоритмы (Карацуба, дихотомическое деление).
- **Рабочая точность `mul`** — сейчас `wp = 2 · prec` с запасом на
  округление. Достаточно `prec + 64`, как в `add` и `div`; уменьшение
  в 2 раза даст ~4× ускорение по времени.
- **`add_raw`** — единственная функция, превышающая порог 50 строк
  (~70). Разбить на `add_same_sign` / `add_diff_sign` целесообразно
  вместе с оптимизацией сложения, а не отдельно.
- **Публичные константы** `ln2` и `e` (сейчас `ln2` вычисляется
  внутри `log`, `e` — через `exp(1)`; отдельных API-символов нет).
- **ULP-метрика** для всех функций: сравнение результата при
  `prec` и `2·prec`, оценка сходимости алгоритма (см. раздел
  «Точность и тестирование»).
- **Бенчмарк** на разных `prec` для всех операций.
- **`set_str` / `get_str`** — парсинг и форматирование строк.
  Сейчас есть только `print`/`print_d` для отладки.
- **Тест на субнормальные `double`** в `set_d`: текущее поведение
  покрыто только косвенно (через `1e10`, `0.5`). Минимальный
  денормализованный (`5e-324`) стоит проверить явно.

## Мотивация

В `s21_math` мы делали `math.h` с точностью `long double`.
Финальная версия (v1.0.0) решала argument reduction problem
даже на Apple Silicon через double-double. Но предел всё равно
оставался: эффективная точность максимум ~226 бит, и она
не масштабируется.

`s21_mpfr` снимает это ограничение: точность задаётся
пользователем от 2 бит до миллионов. Это позволяет:

- Вычислять `sin(1e10)` с точностью `2^-1000`, а не `2^-16`.
- Реализовывать произвольную точность для криптографии
  (RSA, ECC) — числа длиной 2048, 4096 бит.
- Экспериментировать с произвольной точностью без потери
  контроля над форматом числа.
