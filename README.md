# s21_mpfr

> **Status:** 🟢 **v1.4.0 (2026-10-10).**
> Библиотека чисел с плавающей точкой произвольной точности на C11.
> Вдохновлено [MPFR](https://www.mpfr.org/), но реализуется с нуля
> в учебных целях.

Собственная реализация библиотеки чисел с плавающей точкой
произвольной точности. Продолжение проекта
[s21_math](https://github.com/pavel-maru/s21_math), где мы
упирались в ограничения `long double` (80/128/64 бит).
Здесь эти границы убираются полностью — точность задаёт
пользователь.

## Что уже готово

- Тип `s21_mpf_t` — число произвольной точности (мантисса от 2 бит).
- `init`, `init2`, `clear` — управление жизненным циклом.
- `set_prec` — in-place смена точности с сохранением значения
  (расширение — точно, сужение — округление RNDN).
- `set_ui`, `set_si`, `set_d` — присваивание из базовых типов.
- `set_zero`, `set_inf`, `set_nan` — специальные значения.
- `set`, `set_round` — присваивание с режимами округления
  RNDN / RNDZ / RNDU / RNDD.
- `cmp`, `cmp_abs`, `equal`, `zero_p`, `integer_p` — сравнения,
  включая корректную работу на числах разных точностей.
- `add`, `sub`, `mul`, `div`, `neg`, `abs` — базовая арифметика,
  корректная при любой точности (включая некратные 64).
- `sqrt`, `exp`, `log` — элементарные функции.
- `pi` — константа π (формула Мэчина).
- `sin`, `cos`, `tan` — прямые тригонометрические функции.
- `atan`, `asin`, `acos` — обратные тригонометрические функции.
- `print`, `print_d` — отладочная печать.
- Низкоуровневые утилиты: `get_bit`, `set_bit`, `msb`, `lsb`.
- `s21_mpf_repl` — интерактивная утилита для экспериментов
  с функциями библиотеки (REPL: команда, аргументы, точность).
- Unit-тесты в `src/test.c`: 30 групп, покрывают все публичные
  функции, режимы округления, граничные значения, малые точности
  (2, 3, 5, 8), точности, не кратные 32 (33, 100, 130), не кратные
  64 при `set_round`, `mul` и `div` на 15 разных точностях, степени
  двойки, round-trip `div`/`mul`, смешанные точности в одной
  операции, in-place смену точности и ULP-диагностику для всех
  трансцендентных функций.

Публичный API не менялся, изменения внутренние.

  четырёх копий логики.

  `mpf_round_up`, `mpf_add_one`.

  почти идентичных функций для `atanh` и `atan`.
- Хелперы `check_binary` / `check_unary` — вместо 13 копий проверок
  `NULL` и совпадения `prec`.
- Диспетчер специальных значений в `add`/`mul`/`div` вынесен в
  `*_special`-подпрограммы.
- Исправления: `cmp(0, x<0)`, `abs(-0)`, `set_d` для субнормальных
  `double`, знак `tan` при `cos = 0`, `sub_raw`.
- Исправление сдвигов мантиссы при смене точности: раздельные
  `dst_count` / `src_count` вместо одного счётчика.

Интерактивный инструмент, ULP-диагностика, фикс `print_d`.

- **`s21_mpf_repl`** — интерактивная утилита (см. раздел «Сборка»).
  Позволяет вызывать любую публичную функцию с любыми аргументами
  и точностью прямо из терминала; поддерживает как биты, так и
  десятичные цифры (суффикс `d`: `77d` == 256 бит).
- **`test_ulp_diagnostics`** — ULP-метрика для всех трансцендентных
  функций (см. раздел «Точность и тестирование»). Для каждой f
  и аргумента x считается f(x) при `prec = N` и `prec = 2N`,
  второй результат округляется к N бит, разница измеряется в ulp.
  Все результаты — 0.0, то есть N-битный результат совпадает
  с правильно округлённым 2N-битным. Это подтверждает, что
  guard-биты `wp = prec + 64` достаточны и систематической
  потери точности нигде нет.
- **`print_d` исправлен для больших `prec`.** Раньше цикл
  собирал мантиссу целиком в `double`, и при `prec > ~1024`
  промежуточная сумма уходила в `+inf` до `ldexp`. Теперь
  собираются только верхние два лимба, младшие учитываются
  сдвигом экспоненты. `pi 1000d` (prec=3322) печатался как
  `+inf`, теперь печатает `3.1415926535897931`.
- **`src/repl.c`** — интерфейс пользователя, отдельный бинарь,
  отдельная цель `make repl`. Не входит в `libs21_mpf.a`.

## Как устроено внутри

### Представление числа

```c
typedef struct {
  uint64_t *limbs;   /* мантисса, little-endian, limbs[0] — младшие 64 бита */
  int64_t   exp;     /* x = (-1)^sign · mant · 2^(exp − prec) */
  uint32_t  prec;    /* точность в битах */
  int       sign;    /* 0 = +, 1 = − */
  int       kind;    /* ZERO / NORMAL / INF / NAN */
} s21_mpf_t;
```

**Инварианты для NORMAL:**

- старший значащий бит мантиссы стоит на позиции `prec − 1`;
- биты выше `prec` нулевые;
- значение `x = (−1)^sign · mant · 2^(exp − prec)`,
  где `mant = Σ limbs[i] · 2^(64i)`.

Значение и `exp` связаны неотрывно: изменение `prec` меняет вес каждого
бита мантиссы, поэтому любая операция, меняющая `prec`, обязана
пересчитать `exp`.

**Специальные значения** (`kind`): `ZERO` (отдельно хранит знак −0),
`INF` (±), `NAN`. Все арифметические функции первым делом их обрабатывают
и только потом переходят к работе с `NORMAL`.

### Нормализация

Центральная операция — `s21_mpf_normalize`. Приводит мантиссу
к инварианту MSB@prec−1 сдвигом влево или вправо и корректирует `exp`
на ту же величину. Сдвиги реализованы едиными функциями
`s21_mpf_shift_left_into` / `s21_mpf_shift_right_into`, которые
принимают раздельно `dst_count` и `src_count`.

### Смена точности

`s21_mpf_set_prec` меняет точность на месте, сохраняя значение.
Опорный инвариант: `exp` не зависит от `prec` и равен «показателю
MSB + 1», то есть вес старшего бита мантиссы — это `2^(exp − 1)`.
При смене `prec` мантисса сдвигается так, чтобы этот вес не
изменился.

- Расширение — точное (сдвиг влево).
- Сужение — округление RNDN (через `mpf_sticky_below` +
  `mpf_round_up` + `mpf_add_one`).
- Спецзначения переносятся как есть: перераспределяется только
  буфер, поля не трогаются.

### Алгоритмы по операциям

| Операция | Подход | Рабочая точность |
|---|---|---|
| `add`, `sub` | выравнивание по `exp` через `shift_right_into`, сложение с carry / вычитание с borrow; для разных знаков — через `cmp_abs` | `prec + 64` |
| `mul` | школьное умножение `mul_mant` (O(n²)); произведение умещается в `2·wp` бит, финальное округление RNDN до `prec` | `prec + 64` |
| `div` | алгоритм D Кнута на лимбах: нормализация делителя сдвигом `s = 64n − prec` до MSB@bit63, `n+1` итераций с оценкой `q̂`, уточнением и add-back | `prec + 64` |
| `sqrt` | метод Ньютона `x_{n+1} = (x_n + a/x_n)/2`; начальное приближение `2^(half_exp+1)` | `prec + 64` |
| `exp` | ряд Тейлора с halving: `y = a/2^s`, `s` подобрано так, чтобы `|y| < 1`, затем `s` раз квадрат | `prec + 64` |
| `log` | atanh-ряд: `y = a / 2^k` (нормализация `a` к `[1, 2)`), `log(a) = log(y) + k·ln2`; `ln2` через `atanh(1/3)` | `prec + 64` |
| `pi` | формула Мэчина: `π = 16·atan(1/5) − 4·atan(1/239)`, `atan` через степенной ряд | `prec + 64` |
| `sin`, `cos` | reduction по модулю `2π` через `reduce_2pi`, затем степенной ряд; π передаётся через `_impl` | `prec + 64` |
| `tan` | `sin(x) / cos(x)`; одна π на весь вызов | `prec + 64` |
| `atan` | для `|x| > 1`: `π/2 − atan(1/x)`; для средних `x` — reduction `a := a/(1 + √(1+a²))` до 16 раз, затем ряд | `prec + 64` |
| `asin` | `atan(x / √(1 − x²))`; π прокидывается через цепочку | `prec + 64` |
| `acos` | `π/2 − asin(x)`; одна π на весь вызов | `prec + 64` |
| `set_round` | округление мантиссы при смене `prec`; режимы RNDN (ties-to-even), RNDZ, RNDU, RNDD | `dst->prec` |
| `set_prec` | in-place смена `prec`; расширение — точно, сужение — RNDN | `prec` |

**Почему везде `prec + 64`?** Каждая операция выполняется
с запасом в 64 бита, чтобы накопленная ошибка округления в младших битах
не проникала в значащую часть результата после финального `set()` в `res`.
Это тот же принцип, что в MPFR — «guard bits».

**Ленивое π.** Изначально каждая тригонометрическая функция считала π
с нуля. Это дублирование вычислений: в `tan` — дважды, в `acos` при
`|x| < 1` — дважды, в `atan(x)` при `|x| ≤ 1` — вообще не нужна.
Теперь π вычисляется один раз на верхнем уровне и передаётся вниз
через `_impl`-варианты. От глобального кэша сознательно отказались:
он нарушает принцип «нет глобальных переменных» и порождает
проблемы thread-safety и привязки к `prec`.

**Почему `div` — Knuth D.** Побитовое деление было простым, но
O(prec²) битовых сдвигов. Лимбовый алгоритм Кнута делает `n + 1`
итераций, каждая — одно умножение лимба на `q̂` и один проход
вычитания, то есть O(n²). Для 256-битных чисел это `4²` против
`256²`, разница по времени порядка 5×.

### История исправленных дефектов

**v1.0.0.** Два дефекта, найденных при расширении тестов:

- `cmp_abs` при разных `prec` собирала мантиссы в `double` (53 бита)
  и теряла младшие биты. Исправлено на побитовое сравнение с padding.
- `mul` при `prec`, не кратных 32, работала в границе лимба вместо
  реальной точности `2·wp`. Экспонента уезжала. Исправлено на
  `temp.prec = 2·wp`.

**v1.1.0.** Дефекты, найденные при структурном ревью:

- `cmp(0, отрицательное)` возвращал `-1` вместо `+1`.
- `abs(-0)` не сбрасывал знак.
- `set_d` для субнормальных `double` давал значение в 2 раза
  меньше: вес LSB мантиссы субнормала — `2^(-1074)`, что
  соответствует `exp_d = −1021`, а не `−1022`.
- `tan` при `cos = 0` всегда возвращал `+inf`, включая случай
  `x = −π/2`. Теперь знак берётся из `sin`.
- `sub_raw` жёстко ставила `sign = 0` после вычитания.
- Сдвиги мантиссы использовали один счётчик для `dst` и `src`.
  При сужении точности старшие лимбы источника терялись
  («1 + 2 при prec=2 равно 0»).

**v1.2.0.** Дефектов не найдено — только структурный рефакторинг.

**v1.3.0.** Дефекты, найденные при доработке `set_prec`:

- `set_prec` меняла `prec` без пересчёта `exp` и нарушала
  инвариант MSB@prec−1: значение молча уезжало. Переписана
  как in-place с сохранением значения.
- `mpf_add_one` не обрабатывала случай, когда `+1` переходит
  в бит `prec` последнего лимба при `prec % 64 != 0`. Мантисса
  после округления имела `prec + 1` значащих бит.

**v1.4.0.** Дефект, найденный через REPL:

- `print_d` собирала всю мантиссу в `double`, при `prec > ~1024`
  промежуточная сумма уходила в `+inf`. `pi 1000d` (prec=3322)
  печатался как `+inf`. Теперь собираются только верхние два
  лимба, младшие учитываются сдвигом экспоненты.

### Разложение по файлам

- `s21_mpf_internal.h` — внутренний API.
- `repl.c` — интерактивная утилита (отдельный бинарь, не часть
  `libs21_mpf.a`).

## Точность и тестирование

### Что проверяется

Каждая публичная функция покрыта unit-тестами: базовые значения,
границы, специальные случаи (NaN, ±inf, ±0), режимы округления,
малые и некратные точности, регрессии на найденные дефекты.

### ULP-метрика

Реализована в `test_ulp_diagnostics`. Для каждой пары `(функция,
аргумент)` считается:

1. `r_lo = f(x)` при `prec = N`;
2. `r_hi = f(x)` при `prec = 2·N`;
3. `r_hi_N = set_round(r_hi, N, RNDN)` — правильно округлённый
   к N битам «эталон»;
4. `gap = |r_lo − r_hi_N| / ulp(r_lo)`, где `ulp(r_lo) = 2^(r_lo.exp − N)`.

Идея самосогласованная — внешний эталон (MPFR, `libm`) не нужен:
если при удвоении точности результат совпадает с правильно
округлённым при меньшей, значит вычисления сходятся. Gap 0 или 1
(единица — двойное округление на границе, редкий но законный
случай) означает, что алгоритм работает на пределе своей точности.

Текущие результаты:

```
  function     N=32   N=64   N=128  N=256
  sqrt(2)        0.0    0.0    0.0    0.0
  sqrt(10)       0.0    0.0    0.0    0.0
  exp(1)         0.0    0.0    0.0    0.0
  exp(-2)        0.0    0.0    0.0    0.0
  log(2)         0.0    0.0    0.0    0.0
  log(10)        0.0    0.0    0.0    0.0
  sin(1)         0.0    0.0    0.0    0.0
  cos(1)         0.0    0.0    0.0    0.0
  atan(1)        0.0    0.0    0.0    0.0
  atan(10)       0.0    0.0    0.0    0.0
  asin(0.5)      0.0    0.0    0.0    0.0
  acos(0.5)      0.0    0.0    0.0    0.0
  pi             0.0    0.0    0.0    0.0
```

Все нули — N-битный результат побитово совпадает с правильно
округлённым 2N-битным. Guard-биты `wp = prec + 64` достаточны,
систематической потери точности нет.

Тест ассертит `gap ≤ 2`. Если однажды кто-то тронет reduction или
ряд Тейлора — таблица покажет, что поехало.

### Планируется: бенчмарк

Замеры времени на разных `prec` (64, 256, 1024, 4096 бит) для
каждой операции. Теоретические оценки сложности:

- `add`, `sub`, `cmp` — O(n) по числу лимбов;
- `mul` — O(n²), школьный алгоритм;
- `div` — O(n²) лимбовых умножений (Knuth D, `n+1` итераций);
- `sqrt` — O(n²) на итерацию, итераций O(log n);
- `exp`, `log`, `sin`, `cos`, `atan` — O(n²·k) на член ряда,
  `k` членов до сходимости.

## Чек-лист структурного программирования

Проверка по семи принципам Дейкстры и их следствиям. Состояние после
рефакторинга v1.4.0.

**Принципы:**

| № | Принцип | Статус |
|---|---|---|
| 1 | Отказ от `goto` | ✅ |
| 2 | Три базовые конструкции (последовательность, ветвление, цикл) | ✅ |
| 3 | Произвольная вложенность базовых конструкций | ✅ |
| 4 | Логически целостные фрагменты выносятся в подпрограммы | ✅ |
| 5 | Каждая группа инструкций — блок | ✅ |
| 6 | Один вход, один выход | ⚠️ арифметика — ✅, тригонометрические обёртки — ранние `return` на спецзначениях |
| 7 | Разработка сверху вниз | ✅ |

**Следствия:**

| № | Следствие | Статус |
|---|---|---|
| 1 | Запрет глобальных переменных | ✅ |
| 2 | Не более одного выхода из функции | ⚠️ см. принцип 6 |
| 3 | Не более одного выхода из цикла | ✅ |
| 4 | Вложенность блоков ≤ 4 | ✅ (максимум — 2) |
| 5 | Размер функций 40–50 строк | ⚠️ `add_raw` (~70), `div_knuth` (~55); на границе — `sqrt`, `exp`, `atan_impl`, `cos_impl` |

**Комментарии к ⚠️:**

- **Pre-checks** (`check_binary` / `check_unary`) — допустимое
  исключение: защита от некорректного вызова, а не дополнительный
  выход из основной логики.
- **Ранние `return 0` на спецзначениях в тригонометрии** — та же
  природа, что pre-checks, но `*_special`-паттерн мешает применить
  то, что `_impl`-функции ожидают только `NORMAL`.
- **`add_raw`** — оставшаяся длинная функция, две ветки по знаку
  в одном теле. Дальнейшее дробление — вместе с оптимизацией.
- **`div_knuth`** — три вложенных цикла (внешний по `j`, уточнение
  `q̂`, add-back). Разбиение по фазам (D3, D4, D6) увеличит
  количество передаваемых параметров и ухудшит читаемость;
  комментарии в коде расставляют фазы.

## Roadmap на будущее

Известные ограничения, не вошедшие в v1.4.0:

- **`set_prec` с явным режимом округления** — сейчас `set_prec`
  всегда RNDN при сужении. Отдельный `set_prec_round(x, prec, rnd)`
  даст доступ к RNDZ/RNDU/RNDD.
- **Производительность**:
  - `mul` — школьное O(n²); Карацуба / Toom-Cook / FFT.
  - `div` — O(n²) лимбовых умножений; Ньютон поверх быстрого `mul`.
  - `sqrt` — фиксированный верхний предел итераций; адаптивный.
- **`add_raw`** — единственная оставшаяся длинная функция, разбить
  вместе с оптимизацией сложения.
- **Публичные константы** `ln2` и `e` как отдельные API-символы.
- **Бенчмарк** на разных `prec` для всех операций.
- **`set_str` / `get_str`** — парсинг и форматирование строк.
  Сейчас REPL принимает только `double` (53 бита) — при больших
  `prec` ввод обрезается до 53 значащих бит.
- **Тест на субнормальные `double`** в `set_d` — минимальный
  денормализованный (`5e-324`) не проверен явно.

## Мотивация

В `s21_math` мы делали `math.h` с точностью `long double`.
Финальная версия (v1.0.0) решала argument reduction problem
даже на Apple Silicon через double-double. Но предел всё равно
оставался: эффективная точность максимум ~226 бит.

`s21_mpfr` снимает это ограничение: точность задаётся
пользователем от 2 бит до миллионов. Это позволяет:

- Вычислять `sin(1e10)` с точностью `2^-1000`, а не `2^-16`.
- Реализовывать произвольную точность для криптографии
  (RSA, ECC) — числа длиной 2048, 4096 бит.
- Экспериментировать с произвольной точностью без потери
  контроля над форматом числа.
